## 开发逻辑与依据

分两阶段应用固定提交的差额，不合并整仓；每项先检查本地调用及测试再迁移，保留本地共享业务边界。Images 新能力仅增加新模型的必要用量/定价解析，不覆盖旧模型收费规则。WS 状态隔离不等同于伪造 Metadata；保留原账号指纹配置且不同 Key/用户/线程不能互相抢占。

### 关键调用与兼容决定

- `openai_ws_pool.go` 给 coder/websocket 增加常驻读循环、有限消息缓存和关闭通知，空闲脏连接不交给新请求。读超时直接切断，后台/轮次预检 ping 使用 10 秒；保留 TLS profile、代理和握手 beta 硬兼容键。池容量配置在 mode router v2 也按已有动态系数生效，但**不**引入 sub2api 的默认系数 5 倍调整，账号请求并发槽不变。
- `openai_ws_execution_scope.go` 从原始请求提取线程/显式会话及 lane，`Forward` 在账号 namespace 或指纹收敛前计算。turn/prewarm/compaction 共用主 lane，memory/guardian 独立；账号粘性不改为内容随机键。HTTP bridge/passthrough 按连接维护状态，不因共享粘性互相抢占。抢占先发关闭帧后取消；后续轮次 429/其他可换号故障不进入 handler 首包重试链。
- `openai_images_direct.go` 为 Image 2.5 白名单构造原生 JSON，只使用已解析字段，不转发任意 extra JSON。生成/编辑/蒙版、流式完成、空输出、错误、数量与实际尺寸有测试。`openai_images_responses.go` 复用账号认证和 TLS 解析，原生 404/405 才有限回退，并在递归中保留 TLS 路由结果；普通 401/429/5xx 保留 TokenRouter 错误策略。后台图片测试使用同一 payload/response 解析并补有限回退。
- `creative_executor_openai.go` 增加 OAuth 分支，继承 worker context、隐藏 Key 和 run 身份、账号代理/TLS，最多返回一张有效图。不调用 gateway handler/RecordUsage，不新增资金动作或持久化素材；已有 API Key 构造分支不改。`creative_public.go` 仅扩展候选，分组图片开关、管理员展示配置和账号白名单继续过滤。
- `billing_service.go` / `openai_gateway_usage.go` 将上游明确声明的图片缓存输入从普通图片输入扣除，按图片缓存价计费，缺明细不推算；拆分只保存在现有 JSONB，不把 token 数计成图片数。新模型目录和精确兜底来自固定 sub2api 源码；旧目录条目逐项保持。分组/渠道覆写、峰值、订阅和创作台按尺寸收费仍是本 fork 原机制，不引入新倍率。
- `advanced_scheduler_core.go` 与诊断共用窗口解析函数，只对 OpenAI OAuth 优先使用 Codex 5h；其他平台/API Key 仍读取 SessionWindowEnd。未观测/过期保持中性，不改变 schedulable，也不绕过质量检测门禁。
- `UpstreamRequestIdHeaderField.vue` 新字段复用 input/HelpTooltip；头名最多 64 字节，存储 ID 最多 128 字节且保持 UTF-8。用量 DTO/导出只为管理端增加字段，WS 为 NULL；原请求 ID、结算幂等、团队使用归属保留。
