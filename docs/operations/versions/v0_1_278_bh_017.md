## 需求与范围

仅 Codex 检测模块调整文字重点色：满血蓝、降智红、失败黄；模型和思考等级重点突出，适用于手动检测及账号首列详情。批量页不直接铺开结果，点击统计分类后才显示相应账号，回答默认折叠。账号管理新增后端分页一致的检测结果筛选。新增按自定义分钟间隔在服务器运行的定时检测计划、固定账号清单（勾选/全选）和每轮可查看历史；沿用 bh.016 的调度联动，不改变原网关、Metadata 回退或其他平台。

同一交付内用户追加：OpenAI 授权/RT/AT 加号自动补邮箱并在满血测试右侧独立展示；批量题目测试入口蓝色；检测实际进度条；单账号超时可配置且默认 120 秒；管理员仪表盘增加全号池满血率、满血/降智/失败/未测等数量并跳转筛选。全部包含在本修订，不新增应用 VERSION 或 Git tag。

## 开发逻辑与依据

1. 抽取质量统计卡、分类结果弹窗与进度组件。统计默认只显示数量和文字重点色，点击 full/degraded/failed 只显示对应结果，点击满血率显示全部；回答用 details 默认折叠、纯文本渲染。手动批量、账号最近详情、定时历史复用结果卡，模型蓝色加粗、思考等级深黄/亮黄加粗，超时值单独标注。
2. 账号列表增加 quality_status 可选查询；通过专用上下文传到既有 AccountRepository，Count、分页、评分过滤池使用同一谓词，不改变旧接口签名。未测试是不存在有效最近结果，质量筛选仅作用 OpenAI OAuth。筛选快照同时传到跨页全选、按筛选批量编辑和导出，避免界面选的是满血而后台操作全量；正常列表无新筛选时不加关联子查询。
3. 新表 codex_quality_schedules 保存名称、间隔、保留数、启用状态和固定 config；codex_quality_runs 保存每轮冻结参数；codex_quality_run_results 保存逐账号结果。每计划最多 500 个独立 OAuth 账号，保存时批量核对存在性与类型。全选冻结当前搜索结果，不扩展未来新账号。首轮等保存/启用后 interval_minutes，后续从前轮完成开始计时，不追补积压轮次；间隔支持 1–43200 分钟，保留 1–100 轮、默认 30。
4. ScheduledTestRunnerService 启停新增独立 15 秒循环，原单账号 cron 不变，复用 AccountTestService 实例批次锁防止本实例手动/定时重叠。数据库 SKIP LOCKED 领取、60 秒计划租约与 15 秒心跳防止跨实例同计划重叠；派发每个账号前再核验 enabled 与运行 ID。领取、续租查询 5 秒上限，停止服务取消任务并最多等待 35 秒收尾。崩溃租约到期后新领取会把旧轮次标为 interrupted，不伪装完成。
5. 暂停/编辑先 FOR UPDATE 锁计划并撤销运行 ID，提交结果对计划执行 FOR SHARE 身份核验，只有当前有效计划才能更新 schedulable。原最近结果、调度开关、scheduler outbox 和定时逐账号历史在同一 SQL 中提交；不允许“调度变了但历史未保存”的半提交。跳过/取消等剩余结果由 runner 补记，ON CONFLICT 不覆盖已经提交的事实。已完成调度修改不会因暂停自动回滚。
6. timeout_seconds 增加到手动请求和定时 config，省略/0 默认 120，显式 10–3600。单账号请求 context 使用实际超时，账号租约为 timeout+30；整轮预算按 ceil(账号数/并发)×(timeout+30)+60 计算，不能因管理员把超时调长仍被固定总时限截断。底层原 TCP/TLS/响应头超时和上游主动拒绝仍可能提前失败，不覆盖这些全站配置。进度只按已收到/已保存的结果数计算，失败/跳过属于已处理，取消轮次保持实际百分比；向下取整避免 499/500 提前显示 100%。
7. 管理员仪表盘新增独立只读 stats 端点，从所有未删除 OpenAI OAuth 的最近结果聚合，不读取长回答、不发起模型请求、不重复计入历史轮次。满血率分母仍为 full+degraded+failed，未测/stale/cancelled 不计入；点击后通过白名单 URL 筛选进入账号管理。日期筛选不改变此“最近结果”口径。
8. 邮箱只补缺失管理信息：JWT 顶层 email 和 profile.email，限制输入大小并校验邮箱格式；授权码/RT 交换后的 TokenInfo、手动 AT/auth.json 创建及导入支持补缺。导入本次去重键生成之后才补展示，保留原 RT/AT 匹配策略。前端本地解析 AT 可预览，授权/RT 返回邮箱可在授权组件展示，独立邮箱列位于满血测试右侧。opaque token 或无邮箱显示未获取，不新增外部验证请求、不承诺签名验证、不覆盖已有邮箱。实际凭据不修改、不在 UI 或文档回显。
9. UI 每 15 秒刷新定时计划/历史摘要，具体回答按分类每页 20 条加载；每轮完成清理超出 keep_runs 的旧历史及关联回答。计划暂停保留历史；减少保留数在下轮完成时生效。敏感题目不复制到通用审计正文，只记录管理员动作，模型输出作为文字处理。

## 风险与后续同步保留点

周期检测会持续消耗上游额度并影响可用号池；配置必须显式确认。全选为保存当时固定集合，不包含未来新增账号。一次关键词结果不是客观智能评测，错误关键词可能周期性停调。历史输入输出只给管理员，不写普通审计正文。

短间隔、大量账号和长回答会增加费用与数据库存储；默认每计划保留 30 轮，上限 100，可按需调小。计划编辑/停用不回滚已完成结果；暂停与网络故障可产生部分轮次，进度和中断状态如实显示。邮箱由管理员提供的 JWT 声明解码，不能当作所有权验证；旧账号不批量后台探测或改写邮箱，没有邮箱显示未获取。单号超时是总等待上限，底层网络阶段配置和上游错误可能更早结束。后续同步保留检测蓝红黄例外、邮箱列顺序、可选超时默认值、历史原子提交与筛选传递；保持包豪斯、Asia/Taipei 与 Metadata 回退，不扩展到其他平台调度。
