## 需求与范围

用户要求每个 OAuth 账号可独立开关：打开使用 metadata 修复，关闭使用原代码方案。范围限定 OpenAI OAuth/兼容 AT 的 Codex 文本出站，覆盖 HTTP、OAuth 透传、WS 和 Chat/Messages 转换；不扩大到其它平台、官方 API Key 或旧 Compact。

## 功能变动

新增 `extra.codex_metadata_repair_enabled` 布尔值，只有显式 true 生效。创建/编辑用公共包豪斯 Toggle，默认 false。已有 metadata 扩展字段保留，优先当前轮 body，并修复头体身份不一致、旧 metadata 覆盖及部分入口漏补。

## 开发逻辑与依据

前期合成请求已复现 HTTP→WS 原始头覆盖已隔离 body、WS setter 丢掉 body-only 字段，以及 body-only metadata 不回填 HTTP 头。修复不依赖“开启透传”，而以独立账号策略控制最终出站。

### 单次快照与可靠来源

`prepareCodexMetadataRepair` 在原始请求还未被类型化转换/账号隔离时收集 `client_metadata`、内嵌 `x-codex-turn-metadata` 与入站请求头；body 当前轮字段优先，安装标识缺失时只接受真实账号的 device ID。只有请求相关 turn ID 和缺省起始时间会生成，不伪造安装设备、线程、sandbox、客户端能力或环境。未知扩展字段保留；非法/非对象或超过 16 KiB 的对象退回原流程，不删除成“完整”假值。

收集结果使用已有账号 namespace 和明确启用的指纹收敛规则隔离一次，保存为小对象快照，再在最后一个出站步骤写入头和体。Header 全部大小写变体先清掉，防止重复值；标识含 CR/LF/NUL 时不生成修复快照。快照不存整包 input/提示词，透传用局部 JSON 修改，map 调用端获得深复制，避免原地写入污染重试。账号独立开关使用当前行，影子账号的身份来源仍使用真正的母账号凭据。

### 各路径如何接入

| 路径 | 接入点与不变量 |
| --- | --- |
| HTTP Responses / OAuth 透传 | Forward 入口建快照，普通/透传构造器在发出前覆盖小型 metadata 和身份头；只有 body 时也能回填头，同账号内部重试复用快照。 |
| Chat / Messages 转 Responses | 在已解析兼容会话提示、尚未类型化重建 body 时收集扩展字段；发送前再次应用头，避免旧兼容桥重设 session 后破坏头体一致性。 |
| HTTP 入口使用 WS 上游 | 保留旧 setter 调用供关闭分支使用，开启时在 setter/旧收敛后恢复统一快照，避免原始头回写隔离后的 body。 |
| WS 上下文池 / HTTP bridge | 每个 response.create 建新快照，后续轮不把旧握手 turn/环境扩展覆盖当前 body；当前帧缺少稳定身份时仍可使用握手会话字段。换账号重试保存真正的原始当前帧。 |
| WS passthrough relay | 首帧同时投影握手和 body；后续帧局部快照不写共享 Gin 状态，避免并发上下行竞争。已建立连接无法逐轮重发握手，每轮信息由 payload 承载。 |
| WS 连接池 | 兼容键加入开关状态，开启时比较稳定设备/会话/线程字段，不让开关两侧或不同稳定身份复用不匹配握手；不把每轮 turn ID 放入池键，保持同会话连接复用。 |

关闭、非法值、非 OpenAI OAuth/AT 或旧 Compact 不生成/使用快照，原控制路径保留。HTTP/WS 入口清除旧账号快照，最终应用还检查账号 ID，防止 failover 泄漏。

## 上游同步与保留差异

本版是 fork 专属 opt-in，未修改 upstream 基线。关闭分支必须保持原流程；后续同步需保留各入口开关分支、未知字段及多轮测试。

## 包豪斯适配

只在账号创建/编辑添加 `bh-policy-section` 策略卡及公共 Toggle：直角、4px 硬阴影、黄色侧线、蓝色开启态、键盘 focus/Space 和减少动画支持；中英文说明默认关闭和能力边界。其它页面、价格/排名色、阴影和接口展示不变。

## 接口数据与兼容性

复用现有账号 extra JSON 的保存/读取，不新增 URL、数据库迁移或应用版本。请求鉴权、计费、模型映射和路由选择规则不改；新开关仅控制 Codex metadata 的出站呈现。旧版不理解新 extra 时自然保持旧行为。
