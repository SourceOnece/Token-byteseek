## 开发逻辑与依据

采用小范围适配，不按上游整文件覆盖。新增模型贯通默认目录、名称归一、路由判断和计价服务：动态完整条目仍优先；缺失才回退本产品，不能让新 Opus 覆盖旧 Opus 5 的模糊查价。渠道显式零价、Fast 覆写、长上下文开关保持原优先级。

DeepSeek 先判账号平台/实际域名。原生 CN 的 store=false/previous_response_id 清理保持；OpenAI 映射账号只补图片字段，不自动改 store。媒体清洗只遍历 input 内容/输出 parts，不递归修改工具参数、用户字符串或任意 JSON 业务对象。

连接关闭用独立子 context，不取消调用方用于计费/重试的 context；先 cancel 让阻塞读取退出，再拿锁关闭解压器/响应体。读完后连接仍可复用。终态收口保留 Codex bare-error 后可能追加 completed/failed 的特殊顺序。票据注入、业务响应观察与用量消费仍走本地原链路。

OpenCode UA 在内置头之后、账号 Header 覆写之前应用，覆盖普通/透传 Responses、Chat、原生 Messages 以及对应连接测试。TLS 选择、业务代理和会话分区不改。Cloudflare 1010 豁免只在原 403 管线增加明确标识判断，真实权限 403 继续计数与冷却。
