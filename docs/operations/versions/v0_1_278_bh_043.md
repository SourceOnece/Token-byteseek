## 开发逻辑与依据

真实生产GetSnapshot读取sched:meta，filterSchedulerCredentials刻意移除access_token/chatgpt_account_id/organization_id；ListSchedulableAccounts原样返回摘要。普通负载批量路径与高级调度都在补取完整账号之前调用Blocks；Blocks使用摘要GetOpenAIAccessToken()，lookup遇空token立即失败。管理状态从数据库完整账号查询，故可同时显示ready/blocked=false。以292与332、basic与advanced四组合临时overlay复现：管理ready，摘要选择均runtime_blocked=1；仅换完整候选或关闭开关即可成功。

最小修复只在目标OAuth摘要缺凭据时补全同ID账号：Blocks先通过resolveTicketLookupAccount读取SchedulerSnapshotService.GetAccount，复用已有完整账号缓存及受限数据库回退；无快照则读仓储。该次补全总预算200ms，nil/error/超时仍拒绝；返回账号必须同ID且仍为独立OAuth，然后用完整Token/工作区/组织参与原codexTicketKey查票。补全期间关闭开关则放弃票据约束，配置换代则不复用旧票。不把秘密写进摘要、不将完整凭据回填共享候选，不新增进程级凭据副本；完整账号路径及最终Apply基于真实Bearer的复核保持。

生产差异仅codex_ticket_service.go的Blocks与一个补全助手；新增codex_ticket_scheduler_metadata_test.go永久回归。isOpenAIAccountRequestBlocked已有调用统一覆盖基础/高级初筛、粘性与WS检查，不逐条修改调度器；不改变出站build/header逻辑。选择此方案而不是恢复上游明文extra或仅账号ID索引，是为保留本地凭据/工作区换代失效。不跳过摘要阶段的检查，避免先选中缺票号再失败。
