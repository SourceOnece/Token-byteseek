## 需求与范围

按用户截图在账号管理现有“满血测试”列追加 Astra/Sol 票据状态和剩余时间，保留已有质量结果入口。只新增观测，不照搬截图“无票暂停模型”的调度行为；不改打票开关、探测频率、转发/鉴权/计费、TLS 或质量检测规则。

## 功能变动

原先只有全局开关与后台缓存，无法看出每号有没有票。现于账号管理原“满血测试”按钮下方显示两行：`Astra 58m03s`、`Sol 58m03s`，每秒倒计时。无票显示“未获 292”，另区分“待采集 / 采集中 / 采集失败 / 票据已过期 / 打票未开启 / 暂停采集 / 模型不支持 / 状态读取失败”。鼠标悬停可查看完整模型 ID、最近采集时间（有记录时）和脱敏原因。

仅独立 OpenAI OAuth 展示；API Key、影子和 Agent Identity 保持原质量列内容。满血详情、满血率、质量筛选和调度联动没有被票据覆盖；不增加新表格列，不把票据有效写成满血，也不因为没票停调。原刷新按钮同步读取票据状态。

## 开发逻辑与依据

复用 bh.033 凭据/配置代次隔离键，从现有加密票据判断可用性，独立保存有限期的脱敏采集状态，不写账号 extra/updated_at。账号页只读取缓存，不触发上游探测；倒计时由服务端时间校准并在本地更新，状态按当前页批量轮询。

| 文件 / 调用关系 | 逻辑与选择原因 |
| --- | --- |
| `codex_ticket_service.go → recordObservation` | 采集前记录 collecting，结束记录 ready/missing/failed 与固定原因码；观测缓存独立 24h TTL，单次写入最多 150ms。成功必须原票据保存成功，不记录上游正文、代理 URL 或 token |
| `codex_ticket_status.go → Status → accountRepo.GetByIDs / cache.GetMany` | 每次最多 100 个正整数 ID、去重、整体两秒；批量读数据库/MGET，不逐行网络查询，不 GetAccessToken、不调用上游。不符合资格的账号返回 eligible=false，已删除账号省略 |
| `ticketModelStatus` | 当前代次/账号/最终模型/token/工作区键必须匹配。有效加密票据优先于刷新失败；过期或缓存缺失不能仅凭历史 ready 就显示有效。collecting 一分钟后未结束回待采集，未知错误只显示 unavailable；原因固定白名单，任意缓存字符串不可透出 |
| `codex_ticket_handler.go → /admin/settings/codex-ticket/status` | 复用已装配票据服务及原管理员鉴权；独立 GET 只读端点，参数不合法 400，内部读取失败只返回通用提示。不修改旧设置接口及账号 DTO |
| `useCodexTicketStatus.ts → codexTickets.ts` | 只查询当前页独立 OAuth，超过 100 分批顺序读；15 秒轮询、每秒共享本地时钟。单调时钟校准服务端时间，避免本机时间偏差。页面隐藏不轮询，恢复刷新；45 秒未成功读取不显示可信有效状态；翻页/卸载 abort 和版本校验防乱序，清理定时器 |
| `AccountsView.vue → CodexTicketStatus.vue` | 在旧 quality slot 内追加两行，不新列；仍可点击质量结果。显示只使用固定文案和状态，API Key 不显示；缺失行不会无限维持 loading。原刷新按钮可主动读状态，不触发采集 |

没有可重用的账号公开字段：票据状态是随 TTL/凭据/配置变化的短期事实，因此不复制进账号 extra、导出或调度缓存；独立查询也不让账号列表主接口因 Redis 故障整体失败。已有 bh.033 有效票无观测记录也可直接显示倒计时，检查时间为空就不猜测。状态读取失败和采集失败是不同事实，必须分开。

## 风险与后续同步保留点

显示的是票据缓存可用状态，不是模型智能程度或官方健康认证；无票仍可调度，不能写“该模型已暂停”。界面是 15 秒刷新快照，不能当作强一致调度依据；已有有效旧票可能在后台刷新失败时仍显示有效。Redis 无法写入观测时可能暂时只见待采集/旧观测，不伪造成功。后台代理在发出请求前就无法解密等全局故障仍需检查全局配置，不能靠单行状态覆盖所有诊断。未来同步保留只读 GET、不因查状态探测、不写账号配置、敏感字段不返回、质量与票据判定分离，以及默认关闭和缺票放行。
