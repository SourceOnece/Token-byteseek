# v0.1.279-bh.001：TokenFlux 主体、ByteSeek 定制与 sub2api 增量

## 元数据

2026-09-30 Asia/Taipei，代码与发布前验证完成，待镜像发布。B0=`4b4648d84bbe963caf25172e6ad36afa58d4181a`；前版 [bh.072](v0_1_278_bh_072.md)。应用版本来自 TokenFlux v0.1.279，为上游版本同步，不因文档编号单独修改。

## 需求与范围

目标是完整采用 TokenFlux/TokenRouter 的新通用架构，再保留 ByteSeek 的包豪斯界面、票据采集/质量检测/调度联动、账号邮箱和会话隔离，最后只补充 sub2api 尚未被 TokenFlux 覆盖的协议功能。旧 Metadata 实验和 Bearer 生成 AT 不恢复；用户已有的 `bh026_to_bh030_comparison.md` 不改。

## 功能变动

### TokenFlux 主体

- 共享价格和无平台分组采用原生规则；旧的 `legacy_group_override` 分支删除，平台额度/分组平台字段按新迁移归档或下线。
- OpenAI/Provider/模型目录、协议目录、单模型路由和管理页面使用 native provider 语义；MiniMax 与 OpenCode Go 的用量查询、平台能力和路由接入补齐。
- WebSocket 复用、窗口边界、断流/取消、模型响应记录、团队邀请边界和原生缓存保持 TokenFlux 的请求生命周期。
- 仪表盘近期用量可以在 Token 数量与实际支出之间切换，缓存键按用户和指标隔离。

### ByteSeek 保留项

票据工作台继续按账号/模型隔离，支持采集、业务代理复验、STATE 注入、异常守护、实际长度筛选、IP 复用和调度联动；质量检测与定时检测继续兼容 OAuth 和 API Key 上游。Responses 的 reasoning history 使用用户、Key、团队、分组、Provider、平台和凭据作用域，7 天 TTL；WebSocket 保留独立线程/窗口边界与抢占关闭顺序，不把一个账号的状态借给另一个账号。OpenCode 会话按 Key、提供商和凭据派生，换号隔离；普通 user_id 不当作会话。包豪斯变量、直角硬阴影、红黄蓝几何元素、统一控件、移动端和深浅主题保持。

### sub2api 增量

- Anthropic 工具名一次性改写，避免嵌套 JSON、重复工具和字符串内容误替换。
- Claude Sonnet 5.5/Opus 5.5：自适应 thinking、工具选择/采样校验、签名思考和 `redacted_thinking` 保真；count-token beta 与 fine-grained tool beta 按模型过滤。
- Bedrock Sonnet 5.5 保留 effort 字段并使用统一模型路由；5.5 价格、Gemini 3.7/3.8 目录及兜底价格补齐。
- OpenAI Codex Images 1.5、2、2.5 使用原生 generations/edits JSON 接口，保留 `n`、mask、尺寸/格式、实际图片尺寸和图片缓存读价；旧 `gpt-image-1` Responses 路径不变。
- Antigravity 混合内置工具、PDF inlineData、CN MiniMax 编程窗口和 OpenCode Go rolling/weekly/monthly 用量适配加入；平台能力目录包含新增平台。

未采用的 sub2api 项目：风险控制用户白名单、Claude reset-credit 管理 UI、Claude-only 客户端隐藏、Antigravity 兼容 keepalive 以及后续 Anthropic usage 小修复。它们属于 sub2api 自己的运营开关或已在 TokenFlux 生命周期中有不同实现；本批不改变 ByteSeek 票据/调度语义，后续若要引入须单独评估和留档。

## 开发逻辑与关键路径

先固定三方 SHA，先把 TokenFlux 的通用路径迁到当前树，再按最终调用链查 sub2api 是否仍有缺口；同一行为不从两个上游重复复制。迁移只追加本地 277–290，旧迁移保持不可变；同模型跨平台的可比较价格使用 `GREATEST` 取较高值，因此原来走较低平台价的请求可能涨价。计费模式/区间/继承规则冲突则中止升级；旧价保存在归档表，归档不继续参与运行计费。图片请求由 `gateway/httpapi` 选择模型，`upstream/openai` 构造原生 JSON，响应解析和 usage 通过 completion/usage 记录。

## 包豪斯适配

使用现有 `--bh-*` 变量、直角 2–3px 边框、4px 硬阴影、自研 Select/Toggle/Dialog、红黄蓝三元素和绿色状态语义。浏览器检查桌面/手机、亮/暗主题、中英文、reduced-motion 的 11 条页面路线及 OpenAI 新建弹窗、键盘焦点和关闭；禁用/保存等由组件测试覆盖，未逐个操作全站所有控件。新增能力接入既有表单，不创建另一套上游皮肤。

## 接口、数据、配置与回退

公开文本/图片入站协议保持；图片 1.5/2/2.5 按模型选择内部原生上游端点。通用后台采用 TokenFlux 的 `/admin/providers`、`/api/v1/admin/providers` 和 pricing-configs，旧通用账号/渠道脚本需要升级；ByteSeek 票据/质量接口保留账号兼容路由，不能笼统说所有旧接口不变。新增单模型 GET 与列表共用 Key/分组/白名单权限。仪表盘新增可选 `metric=actual_cost`，缺省仍为 tokens，缓存按指标区分。

新迁移不可与旧实例混跑：升级前备份数据库，旧平台字段和重复控制按 277–290 顺序归档/删除。旧 `gpt-image-1`、票据关闭开关、双链路默认关闭及原有定制调度规则保留。普通配置和票据为两阶段保存，若后者失败，弹窗明确提示“普通配置已保存，票据未保存”，保留草稿供修正重试。发布镜像不等于替换线上容器，回退需配套数据库备份。
