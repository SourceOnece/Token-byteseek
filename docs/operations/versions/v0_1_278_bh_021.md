## 需求与范围

用户要求账号管理搜索框支持账号邮箱搜索，其他不变。复用 search 参数，支持完整/部分邮箱、不区分大小写；保留名称搜索、分页排序和已有筛选。只读取已保存邮箱，不解析 Token、不查询上游、不改账号、调度、接口结构和 UI。

用户进一步确认：名称和邮箱共用原来的一个搜索框。本次没有新增邮箱输入框或搜索方式切换，也没有修改原搜索框模板。

## 功能变动

| 搜索范围一致性 | 名称查询共用 | 邮箱查询也在 Count/分页前应用，供全选、筛选导出及批量操作共用 | accountListFilteredQuery |

## 开发逻辑与依据

后端名称谓词保持原样，以 OR 增加邮箱字符串谓词；显示邮箱优先 credentials.email、extra.email_address、extra.email，影子账号再回退未删除母账号的 credentials.email。只检查邮箱键，不搜索凭据 JSON 全文。邮箱模糊匹配转义 LIKE 特殊字符，查询参数绑定。前端局部更新复用已有 accountDisplayEmail，防止按邮箱搜到的记录因局部刷新被移出列表。

邮箱包含搜索使用 JSON 字段及影子母账号查找，超大号池查询性能需按实际数据评估，不在本次擅自加索引或迁移。只匹配显示邮箱，不搜索隐藏备用值和 access token。未保存邮箱无法凭搜索自动获取。
