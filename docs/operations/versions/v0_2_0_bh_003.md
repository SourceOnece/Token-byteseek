## 功能变动

管理员 → 系统设置 → 通用设置 → 站点设置 → 界面主题，默认 TokenFlux，可选包豪斯。选择后点页面原有“保存设置”按钮才生效；未保存或保存失败不改变当前皮肤。重新进入设置页回显已保存值。

bh.002 的用户顶栏、公开首页及认证页皮肤选择器全部移除；管理员顶栏也不另设入口。保存成功后管理员页面应用，其他用户刷新/重新加载时读取统一配置。旧 `visual-theme` 本地存储不再参与决策、不写入新值。原有浅色、深色、跟随系统独立保留，与这里的页面风格无关。

## 开发逻辑与依据

实际镜像浏览器验收暴露了已有整页保存缺陷：前端自动提交 `minimax`、`opencode_go` 的调度阈值，后端 `AllowedSchedulingThresholdPlatforms` 只接受 OpenAI、Anthropic、Grok、Kimi、Zhipu，导致 400 `INVALID_PROVIDER_SCHEDULING_THRESHOLDS`，包括主题在内的设置都无法保存。本次将前端列表/类型/默认序列化收拢到这五个平台，并增加保存载荷断言。不放宽后端校验、不新增阈值评估，也不移除 MiniMax/OpenCode 的账号与网关支持。该修正是让原设置按钮真正可用所必需。

新增 `site_theme` 站点键，复用现有 settings 静态参与者和原子准备/提交，不增加另一套设置存储。site 独占该键；综合 DTO、快照、读取/写回投影和审计补齐字段，字段所有权契约从 288 增为 289。管理员非空非法值返回 400，准备阶段失败不落其它字段；旧客户端省略此字段走原 omitted-key 过滤，保留当前配置。缺失或历史非法值在读取时回退 tokenflux，显式空值恢复默认。

公开设置 API 和服务端 HTML 注入均返回规范化主题；`main.ts` 以注入值首屏初始化，app store 统一应用后续配置。保存成功沿原流程强制刷新公开设置。应用挂载也强制复核一次公开配置：HTML 注入缓存是进程内缓存，没有 TTL 或跨实例通知，因此另一个实例可能仍注入旧值；这一复核保证刷新后最终采用数据库新值。失败保留已有有效主题，不在失败时回退默认，不轮询、不推送已打开的标签页。

## 风险与后续同步保留点

HTML 缓存没有 TTL；同进程通过设置更新通知失效，多实例可能首屏短暂出现旧主题，随后挂载时公开配置复核更新。网络不可用时保留注入/当前主题，恢复网络后刷新。已打开用户页面不主动推送主题。不得重新将写入入口开放到普通用户菜单或按浏览器偏好覆盖站点配置。
