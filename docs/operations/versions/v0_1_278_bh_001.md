## 开发逻辑与依据

### 分组页签：保留状态和校验，再适配视觉

沿用上游 `GroupFormTabs.vue` 的持续挂载与 `v-show` 结构，不以卸载组件缩短表单，避免内部定价和推理规则草稿丢失。切换平台后修正不可见的当前页签；切换页签后重置滚动。原生无效字段和引导共用显露路径：切换目标页签 → 派发 `form-field-reveal` 展开折叠定价条目 → 等待 DOM 更新 → 滚动/聚焦或报告校验。键盘方向键、Home/End 和 ARIA 保留。

`GroupsView.vue` 接受上游字段重排，再恢复创建/编辑中四处 OpenAI Fast 策略卡的 `bh-policy-section`。公共开关负责统一外观，页签首块的边线简化规则排除独立策略卡，防止硬边框缺一边。手机从横向页签改为两列，解决入口被裁切，不变更提交字段和保存逻辑。

### 目录与定价：上游业务变化独立于视觉

接受上游共享模型身份候选解析：优先完整模型，再兼容明确的名称和同产品档位别名；目录完整条目独立生效，不跨型号拼价格、上下文或能力。渠道首先匹配原始请求规则，再查询候选，显式零价仍有效，分组价优先级和平台隔离保留。未知目录也可以命中已配置渠道价，而未知价格不能被视觉层填为零。

默认裸 `gpt-5.6` 的移除同步到后端预设、前端白名单及 OpenCode 配置导出，不伪装成纯 UI 调整。具体边界由[模型目录与市场](../../interfaces/model_catalog_and_marketplace.md)及新测试约束；fork 未另改后端解析逻辑。

### 共享视觉：修在公共入口而非逐页覆盖

给分组、账号、Key 菜单统一加 `.bh-action-menu`，保留菜单事件、危险操作和视口定位。全局菜单样式负责硬阴影、红色侧线、黄色悬停和焦点；深色 scoped 旧 hover 背景优先级造成黑字深底，因此只在公共菜单的 hover/focus 规则中显式覆盖背景和文字。图标 hover 继承文字色，避免黄图标落在黄底。

`Toggle.vue` 用不改变布局尺寸的内描边和硬阴影保留 sm/md 的滑块行程，禁用、键盘和 ARIA 仍由上游逻辑负责。`DataTable.vue` 修正固定表头及固定列使用的主题变量，不改排序、分页和数据。TF CLI 黄色提示区的字色固定为墨色，避免深色主题反转成浅字黄底。

## 上游同步与保留差异
