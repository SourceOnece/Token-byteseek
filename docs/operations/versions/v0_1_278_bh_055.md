## 开发逻辑与依据

沿用已有账号接口与私有票据配置接口，由父表单统一协调；先准备和校验票据快照，再保存普通表单，最后保存票据。两部分不是一个跨接口事务，失败必须明确提示并保留弹窗，不把部分成功显示为全部成功。新号保持原创建事务。

共享组件prepareSave等待对应加载完成，校验勾选项、整数范围、模型数量和可同时判断的规则冲突，返回绑定账号ID/revision/组件代次的提交闭包。普通账号失败不执行闭包；批量普通保存不是全部成功时也不写整批票据。纯票据批量跳过普通空请求。组件切换账号/销毁后旧闭包拒绝提交，不丢掉原revision冲突保护。保存期间禁用表单，重复点击由提交状态拦截。

折叠使用v-show持续挂载，代理密码等草稿不因收起销毁；隐藏fieldset同时禁用，避免不可见非法数字拦截浏览器提交。关闭时只保存关闭状态，不清空旧规则，也不提交隐藏草稿。重新展开可以继续修改本次草稿；关窗后未提交草稿按原行为丢弃。双链路强制有效守护但保留原守护选择的逻辑不变。
