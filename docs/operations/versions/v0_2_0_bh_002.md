## 开发逻辑与依据

### 单页面、双皮肤

useVisualTheme 独立保存 visual-theme（tokenflux/bauhaus）；无记录或非法值默认 tokenflux，localStorage 不可用时仍可切换当前页面。main.ts 挂载前初始化，使用根 data-visual-theme 属性选皮肤，没有按主题复制路由、维护两份表单或重新挂载页面。

style.css 跟随上游基础配方和动效；styles/visual-palette.css 为同一组 Tailwind 颜色、阴影、背景工具类提供 CSS 变量；styles/bauhaus.css 限定于包豪斯根属性，覆盖直角、三原色、纸色、几何背景、硬阴影和按压。没有动态插入第二份完整 Tailwind 样式表，避免两个全局重置和明暗规则争抢。上游 dark 阴影清除有 important，因此包豪斯用作用域更精确的覆盖确保深浅一致；暗色辅助文字/链接另校正对比。

VisualThemeSelector 复用 Select 的键盘、焦点、浮层、外部点击与视口定位，不新增原生 select。useTheme 负责 light/dark/system；旧 theme 偏好继续有效。useChartTheme 色板响应式更新，Chart.js 默认值在原生/包豪斯之间恢复，切换不丢筛选、会话、表单草稿或已加载数据。

### 完整界面/动效接入与定制合并

以 TokenFlux 0.2.0 页面和公共组件为目标，对有业务扩展的文件进行三方比较；不能以旧皮肤为由保留整页旧实现。保留或重新接入：

- 账号管理的邮箱列/共用搜索、检测结果、真实票据长度筛选、手动/定时检测和采集入口。
- 票据工作台的账号配置、导入模板、勾选批改、共同值/不同值、统一保存、部分成功提示及草稿保留。
- 管理员满血统计及筛选跳转、响应模型显示、已有三态调度规则的界面投影。
- API Key 批量编辑、创建时协议筛组及订阅边界、凭据轮换成功后更新本地记录。
- 分组额外白名单、用户批量删除的固定确认快照、订阅批量操作、代理有效期、站点计费模式、团队邀请限制及 Asia/Taipei。
- MiniMax/OpenCode 类型、端点/协议预设、账号套餐识别、原生图片字段与精细价格展示。
- 注册确认密码、关闭注册时隐藏入口、查询过时响应隔离、图片读取取消、部分退款按本次金额判断、导出条件快照、数值分页跳转和 TOTP 返回上一步后的输入同步。

以上业务仍调用既有服务。导入默认值的模型/映射保持两列，同时使用上游稳定行编辑器；普通配置与票据沿原 prepareSave 提交顺序，失败时不把部分成功伪装成全部成功。Select 保留滚动后重新定位等本地边界；BaseDialog 保留 showCloseButton 供批任务控制关闭。

用户仪表盘以 TokenFlux 本轮最终结构为准。上游没有原 ByteSeek 的独立八统计卡/模型分布圆环；模型 Top 5 可联动筛选，使用记录中仍能看分布。查询失败提示和重试继续保留，过时结果不发布。
