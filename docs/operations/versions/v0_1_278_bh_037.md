## 开发逻辑与依据

bh.036 的 ticketModelStatus 会用有效旧票覆盖观测 state，UI 又在 ready 时隐藏诊断，导致最新失败不明显。手动的跳过/取消及 IP 结果也未写独立最近展示。此次以配置/凭据/账号/模型隔离的独立展示缓存保存最近完成记录，原 status 仍用于后台重试；不拿展示字段决定调度。

自动 probe 结束写 latest，手动 collectModel defer 记录整个模型任务的完成结果，包含本批最新 IP 诊断；配置/凭据变化的旧 key 不会被当前账号读取。Redis SetLatest 用 Lua 比较 finished_us，乱序旧回写直接忽略，值整体最多24h。单次写150ms预算失败不阻止业务。状态接口同批 MGET 读取 latest，并白名单收口枚举/代理ID/IP后返回；代理名称从当前配置关联，旧版本没有 latest 则保持旧展示。微秒比较使用实例时钟，需要时钟同步，不声称跨实例时钟完全准确。

UI 从 optional latest 取主行状态，当前有效性仍取原 state/blocked/expires_at，最新失败时旧有效票继续绿字倒计时。手动每号完成 emit result，父 AccountsView 请求状态刷新；composable 在已有请求执行时置补读标志，多事件只补一次，不反复取消大页请求。分页/组件销毁取消和隐藏页行为保持。

IP 默认查询原为两个 HTTP 地址并共用四秒，可能被代理限制域名/协议、第一端点耗尽预算；没有生产代理实测，不能断言这是线上唯一根因。新增手动专用 HTTPS 查询不影响全站代理测试；仍为独立请求参考值，不证明采票连接出口。

专用 ProbeTicketReferenceIP 方法默认先 ChatGPT HTTPS trace 后 HTTPS ipify；管理员自定义端点优先。保留证书/DNS等原校验和代理配置，不直连兜底；客户端副本禁重定向，单端点五秒、总十一秒，正文8KiB上限，IP解析通过才存储。新历史存ip_status/source/http_status，不存完整URL或原始错误。没有采集HTTP响应记not_attempted，不用额外IP流量掩盖原采集网络故障。
