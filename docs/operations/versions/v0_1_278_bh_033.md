以下为实际落地范围；是冻结增量的兼容同步，不是两个上游整仓覆盖。

### 小白使用说明

普通用户不需要配置。管理员只在想试用“292 打票”时去 **系统设置 → 网关服务 → OpenAI → 292 打票（可选）**，填采集用代理并打开开关，再点“单独保存票据设置”。代理留空表示保留已有配置，不是删除；清除需勾选。业务仍走每个账号原来的代理。多实例需共用 Redis 与固定的 `TOTP_ENCRYPTION_KEY`，不要为了本功能随意更换现有加密密钥。关闭后不再采集或补票，不会把现有账号变成停调。缺票、失败不保证有可见效果，也不等于账号降智。

暂停账号继续刷新令牌，可以减少恢复调度时发现令牌过期的情况；不会自动打开账号。断线后保存续聊归属，是避免客户端刚收到回答就断线时索引来不及保存，不是替用户重发请求。协议兼容修复只在相应供应商路径执行；兑换页可以翻历史页，不再只看到最近 25 条。

## 开发逻辑与依据

按功能适配已有服务，不整文件覆盖。后台修复复用包豪斯组件；账号刷新与调度分别控制；协议转换仅在已选出的适用平台/实际目的地生效。票据改变上游请求行为，需与原 turn-state、TLS profile、质量测试、配置变更和跨实例运行共同审查，不把长度视为满血保证，不承诺解决所有 overloaded。

### 关键实现与调用关系

- `account_repo.go → ListOAuthRefreshCandidatePage → TokenRefreshService`：只去掉 schedulable 候选过滤；保留 SetupToken/Qoder/Grok 及原状态/限流条件。刷新不回写人工调度。
- `openai_gateway_response_handling.go → bindHTTPResponseAccount`：以 `context.WithoutCancel` 保留上下文值，再加现有 Redis 超时预算，按原 group/user/Key 写账号归属与 owner。
- `openai_chat_roles.go → openai_gateway_chat_completions_raw.go`：平台或精确官方目标主机才转换 developer；RawMessage 保留未知字段/大整数。`responses_tool_output_media.go → normalizeDeepSeekResponsesRequestBody` 只对 DeepSeek 处理图片，复制工具对象，保留重试原输入。
- `gemini_messages_compat_service.go → GeminiV1BetaListModels`：实际可调度 Antigravity 映射与原生列表去重合并，保留混合调度 opt-in、自定义列表、复合 Key、别名投影及最终白名单；强制 Antigravity 列表改为实际映射而非常量。
- `redeem_handler.go → RedeemService → ListByUserPaginated → RedeemCodeUsage`：保留本地一码多用/套餐，不照搬上游仅按 used_by 的语义；`api/redeem.ts → RedeemView → Pagination` 保留旧 getHistory，新增分页方法及乱序保护。
- `Wire → ProvideCodexTicketService → OpenAIGatewayService`：独立后台生命周期，每两秒拉运行时配置，每分钟最多一轮，集群 Redis 轮次/单模型租约，最多四并发、轮次 30 秒、单探测 25 秒，沿用账号并发槽且跳过停调账号。只探测独立 OpenAI OAuth 的 `gpt-6-astra` / `gpt-5.6-sol`。
- 票据只从探测的 200 响应头读取，筛选 292 字节及约定前缀；最长一小时是本地缓存政策，不是官方有效期承诺。Redis 键包含配置代次、账号、最终模型、token、工作区/组织的哈希，正文 AES-GCM 加密。保存设置、换凭据/工作区后旧票据不可复用；不写账号 extra/outbox/updated_at。
- HTTP、passthrough 与 WS 握手构建器共用 Apply：关闭不读票据缓存；开启只补缺失 turn-state，已有值优先，缓存读最多 200ms；无票或故障仍沿用原请求。Messages/Chat 转 Responses 经公共构建器获得同样能力；独立连接测试/质量测试不注入，采集不计入用户账单。
- `CodexTicketSettings.vue → /admin/settings/codex-ticket → CodexTicketService.Update`：独立管理员 API，代理仅写不回显，加密存 settings，审计整字段脱敏；保存失败保留草稿，加载失败禁止误覆盖后端。关闭取消采集轮次，但不主动断开已建立的业务 WS；正常跨实例关闭约两秒生效，设置失联超过十秒不沿用旧开启状态。

### 与票据上游方案的有意区别

不采用“缺票阻止候选”、无条件覆盖客户端状态、票据写账号普通配置；使用默认关闭、缺票放行、私有加密 Redis、凭据与配置代次隔离及有限探测。采集走独立代理的 H1 短连接并禁止重定向，不改变正常业务 TLS 模板/代理，也不恢复旧 Metadata 实验或 experimental beta。Astra 的探测客户端最低版本仅作用于合成探测。保留本地多用户会话隔离并不证明上游 opaque turn-state 在不同会话复用完全等价，真实效果需要管理员小范围验证。
