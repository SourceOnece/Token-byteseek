## 需求与范围

用户要求只解决 `stream disconnected before completion: Our servers are currently overloaded. Please try again later.`，授权参考官方 Codex。保持已有逐账号开关与默认关闭，不靠替换模型、吞掉错误或伪造成功来改变表面结果。

## 功能变动

纠正 bh.003 将完整 metadata 复制到 header 的假设：body 完整保存，header 按官方兼容投影排除工具库存并有界；当前请求类型有确定来源时补齐，保留未知字段与 Unicode。真实容量故障仍按既有有界重试和失败语义处理。

- 完整 metadata 处理上限为 256 KiB，兼容 header 保持 16 KiB；工具库存只保留在 body。合法 body 的兼容投影仍超限时省略可选 metadata header，不截断完整 body。
- 缺失 `request_kind` 时，从当前请求选择 `turn`、`prewarm` 或 `compaction`；已有类型保留，不猜测 sandbox、workspaces 等客户端事实。
- ASCII JSON 保留中文/emoji 可逆表达；未知大整数使用 json.Number，不再经旧内嵌 metadata 解码器的 float64 往返。
- 网关主动 WS 预热在深层元数据副本中标记 prewarm，不污染正常 turn；已有指纹 session 模式仍从原始客户端 session 派生线程，而不是重复账号隔离后的值。

## 开发逻辑与依据

官方 [responses_metadata.rs](https://github.com/openai/codex/blob/7bab4526f9dfd0792e115f1e3183cb06342beb6a/codex-rs/core/src/responses_metadata.rs) 定义 body 的 `client_metadata["x-codex-turn-metadata"]` 为完整来源，`compatibility_headers` 排除 `tool_namespaces_info` 且使用 ASCII JSON。旧实现用统一 16 KiB 限制、全段复制，可能在工具库存较大时放弃修复或把 body-only 库存放进请求头。

官方 [SSE 解析](https://github.com/openai/codex/blob/7bab4526f9dfd0792e115f1e3183cb06342beb6a/codex-rs/codex-api/src/sse/responses.rs) 与 [错误映射](https://github.com/openai/codex/blob/7bab4526f9dfd0792e115f1e3183cb06342beb6a/codex-rs/codex-api/src/api_bridge.rs) 显示，收到带 message 的可重试 response.failed 也会产生 Stream 错误；该提示不必然意味着 TCP 断开。项目原来将容量码在客户端副本改成 `server_error`，因此文案前缀不是定位网络故障的充分依据。本版不以改文案掩盖错误。

### 代码与选择依据

[openai_codex_metadata_repair.go](../../../backend/internal/service/openai_codex_metadata_repair.go) 分别生成完整 body 和精简 header。identity 先从原始输入收集，对 flat 与内嵌字段调用现有账号隔离；内嵌的其它元数据独立保留，避开旧隔离函数对 JSON number 的精度损失。可选指纹收敛仍复用原函数，session 派生输入保存隔离前值，最终共同身份从同一快照投影。

[openai_ws_forwarder_support.go](../../../backend/internal/service/openai_ws_forwarder_support.go) 只在 metadata 修复开启时对主动预热副本调整 request_kind。[回归测试](../../../backend/internal/service/openai_codex_metadata_repair_test.go) 增加库存大小、Unicode/大整数、请求类型与预热副本不变性；不修改通用错误改写器或重试预算，以免变成掩盖错误/无限重放。

安全上限属于本 fork 的资源保护策略，不把 256 KiB/16 KiB 宣称为官方 API 配额。超限/非法 body 保持旧路径并在验证中明确，不能伪装成“所有 metadata 都完整补齐”。

## 验证记录

### 本地回归

Go 1.27.0 禁网容器执行原 metadata/身份/指纹、WS 连接池、HTTP/WS 透传和 Chat/Messages 转换相关套件及管理开关保存测试均通过，原始 session 派生断言补充后再次通过。命令为 `go test ./internal/service -run 'TestCodexMetadataRepair|TestCodex.*Identity|Test.*Fingerprint|TestOpenAIWSConnPool|TestOpenAIGatewayService_.*(WS|Passthrough)|TestForwardAsAnthropic|TestForwardAsChatCompletions' -count=1 -timeout=4m`，另运行 `go test -tags=unit ./internal/service -run '^TestUpdateAccount_CodexMetadataRepairToggle$' -count=1`。新增测试覆盖超过 16 KiB 的工具库存仍完整保留、header 不含库存、中文/emoji ASCII 往返、9007199254740993 精度、超限兼容头省略、turn/prewarm/compaction 和已提供 memory 类型保留、预热不修改正常请求。无前端变动，不重跑 UI 全量测试；镜像构建会验证嵌入前端。

### 远端 gpt-6-astra 长流

使用用户授权的测试站普通账号，创建配额 0.5 USD、有效期 1 天的临时 Key，仅发两次请求，然后删除成功（200）并确认读回 404。输入为用户鹈鹕骑车 HTML/SVG 提示词，固定 model=gpt-6-astra、effort=low、stream=true，要求独立 HTML、不依赖外部资源。两请求同 session，第二条额外携带请求侧 request_kind/session/thread/turn/时间，未伪造设备或环境字段。

| 变体 | HTTP / 终态 | 首输出 | 总耗时 | 输出 |
| --- | --- | --- | --- | --- |
| 无请求侧 metadata | 200 / response.completed，模型回显 gpt-6-astra | 23.86 秒 | 69.26 秒 | 1444 tokens，3434 字符，包含 SVG 和闭合 html |
| 请求侧 request_kind=turn | 200 / response.completed，模型回显 gpt-6-astra | 3.10 秒 | 39.31 秒 | 1225 tokens，3127 字符，包含 SVG 和闭合 html |

两条均完整读取终态，没有只凭 HTTP 200 判断成功。远端尚未部署本轮修正，因此这两次不是新代码上线后的对照验证，也不是服务端开关 A/B。使用普通账号仍无法确认后台开关、锁定同一上游 OAuth 账号或更新远端部署；不能把耗时差异归因于 metadata。

## 风险与后续同步保留点

必须保留官方 body/header 不同职责，不能为了“完全一致”把无限工具信息塞入 header。修复已确认协议缺口不等于远端 overloaded 根因已证明，需明确区分本地回归、远端部署和实测因果。

## 追加证据与勘误

2026-09-07：官方源码显示“完整 body = 完整 header”的旧描述不正确，本版显式更正现行契约；bh.003 历史记录保留当时实现事实，由本记录解释替代原因。此前实测 overloaded 仍作为有效失败证据保留，不用本轮两次长流成功覆盖它。
