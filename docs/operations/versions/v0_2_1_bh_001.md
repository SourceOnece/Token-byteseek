# v0.2.1-bh.001：TokenFlux 全功能跟进与定制保留

## 元数据

2026-10-02 Asia/Taipei，完成验证、源码推送及镜像发布，未部署。主体实现 012aee778fbd5af32ebb4a75654d7e8b158dbf15，手机微调及最终镜像源码 2a41e2f7b208407863272a2dbcec5964cfe64dce；起点 cc89f231fecdcad816637deea2b2622699f6dceb。承接未发布的 [0.2.0-bh.007](v0_2_0_bh_007.md)，前一已发布应用为 0.2.0-bh.006。源码 VERSION 随 TokenFlux 更新到 0.2.1，发布构建注入 0.2.1-bh.001。

## 需求与范围

用户明确：TokenFlux 全量同步，保留 ByteSeek 定制；sub2api 按必要增量。TokenFlux 通用功能和有效修复全部纳入；保留管理员双皮肤、共同首页结构、票据与质量检测、调度联动、邮箱、TLS 和隔离。不恢复明确撤回的 Metadata 实验或生成 AT。

## 功能变动

本批完成提供商分页表单及授权步骤、统一设置组件、可选协议和批量模型连接测试、图片 URL 返回兼容与避免重复生图、TPM 数字格式及图标焦点修复。上一未发布批次的兼容/传输修复一并纳入。另修复热力图跨夏令时日期漂移，以及连接测试关闭/重开时迟到响应污染新一轮状态。

## 开发逻辑与依据

以已核对的 TokenFlux 7ac89a465 为三方比较基点，逐文件合并新增功能，冲突处保留 ByteSeek 业务连接和上游新交互。连接测试与质量题目检测继续分开：通用连接测试不会改动质量结论与调度。票据配置沿用账号保存及批量勾选语义。

- 新增、编辑及批量使用 `common/settings/SettingsTabs` 等公共组件；票据作为同一弹窗的“账号票据”页签，保持统一保存、总开关折叠和批量勾选。新增 OpenAI 在授权第二步隐藏而不卸载草稿；其它平台沿上游的步骤挂载规则。原邮箱识别重新接到新授权模板。
- MiniMax/OpenCode 沿已有扩展平台类型接入 `ProviderChoiceCard` 与分段选择，保留 Zen/Go、协议规则和独立端点；新测试页及后端测试准入也纳入其已启用协议，防止只出现选项却无法执行。补齐平台图标组件导入和两张新色表。
- 单模型和批量模型连接测试共用 `providerTestRun`；批量上限 50，支持并发 1/2/3、停止未开始项及失败重试。批次序号和单次结果序号隔离旧异步返回，模型列表也按账号/弹窗代次接收；卸载取消请求。它不调用 quality 的关键词判定，也不覆盖 ticket 的采集结论。
- `creative/provider/openai.go` 优先 Base64，必要时从 URL 下载；下载走原目标校验和账号代理，不携带生图凭据。响应先关闭再下载以释放连接；最多下载三次，失败返回独立错误，不重新生成。`worker.go` 保留原失败释放预占与用量边界，OAuth 原生图片增量保留。
- `UserDashboardHeatmap` 用本地正午遍历日期，防止跨夏令时凌晨漂移导致当天被标未来。批量编辑校验异常改为显示错误并停止保存，新账号集合读取前清除旧票据资格，避免旧选择残留。
