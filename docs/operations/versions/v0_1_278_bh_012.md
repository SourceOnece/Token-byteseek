## 开发逻辑与依据

截图仅声称缺失 Metadata 与 overloaded 有关，不提供完整字段清单或官方根因。2026-09-07 拉取官方 Codex main=455318c2020d75ae7d66d6ccf19defda97edec34；responses_metadata.rs、turn_metadata.rs、client.rs 与前次核对内容无差异。OpenAI Docs 搜索服务 502，源码直接读取成功。官方完整 body 字段、兼容 flat、HTTP/WS header、Memory 省略和请求种类分别核对，不伪造客户端设备/工作目录/权限事实。下列实现和矩阵对应真实代码与执行证据，不把截图经验当作上游因果证明。

### 最终实现与非破坏边界

统一核心仍先检查 IsCodexMetadataRepairEnabled 和旧 Compact 排除；所有新增投影、校验、WS 默认值和更新帧逻辑均在开启侧。HTTP/Chat/Messages 的原构造顺序保持，WS ctx_pool/http_bridge/passthrough 共用同一个核心；完整合法 body 不经其它 float64 解码丢失大整数。scope/指纹函数、模型工具策略、账号/分组、鉴权计费与 root prompt_cache_key 没有生产代码差异。

恢复 bh.011 曾省略的 WS x-codex-turn-metadata、x-codex-parent-thread-id、x-openai-subagent 首轮兼容头；首轮建连使用同一快照，后续每帧完整 body 使用当前轮信息。回合元数据不参与池硬兼容键，稳定账号/设备/session/thread/window/原追踪兜底、beta/TLS 隔离不变。真实 x-openai-memgen-request=true/false 只在有效开启快照投影；不推测 MemoryConsolidation 资格。

新增 codexMetadataSession 只活在当前 WS 入站生命周期；原始 installation/session/thread/window 与父线程/分叉/子代理来源可补后续缺省项，不保存 prompt、token、工具库存、环境快照、turn、parent_turn、root_turn、时间或请求类型。显式 session/thread 改变清理旧线程来源；null/空串有清除标记，后续省略也不从旧头或指纹重生。Memory 不借普通线程父子来源，也不覆写普通会话默认值。透传使用候选状态，原 Fast/权限/模型策略通过后提交，拒绝帧不污染后续状态。

session.update 是既有透传兼容行为（官方 Responses 主协议只有 response.create，Realtime 独立路由不在此次改动范围）。开启侧只规范它明确声明的 client_metadata 键，不新增完整 blob/turn/时间/request_kind，也不修改 session.instructions/model/tools；关闭继续原路径。首轮明确完整 body 与兼容头有相同 turn ID 时补入缺失扩展；无 body blob 可使用首轮头；不同/未知回合不混入旧环境、Memory 类型或时间。

当前安全重放仍由旧 WS HTTP bridge 及 handler 判断，不改 replay payload。只有源账号开启、旧路径认可可重放时，在当前 Gin 入站存一份单次原始稳定来源，绑定 API Key 与 payload SHA-256；目标开启才消费并按新账号重新隔离，目标关闭丢弃。使用 Gin 入站作用域而不是 Request 指针，是因为原 Ops 链路会 WithContext 替换 Request；真实第二轮 429 测试发现这个区别并修正。HTTP 同账号修复快照允许共享 URL/Body 的合法 Request.WithContext 浅副本，来源摘要仍必须一致；真正新请求有新 URL 对象，不跨请求复用缺省 turn。
