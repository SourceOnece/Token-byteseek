## 需求与范围

用户拒绝上一轮全部优化建议，仅新增账号勾选后的手动批量采票，沿用网关服务 OpenAI 设置，类似批量质量检测展示进度、每轮每次结果、代理与 IP。后续明确补充：尝试轮数不设原十次上限，以填写值为上限；合格票据长度可自定义。按每账号每模型的最大尝试数实现，成功即停，认证/限流/取消可提前结束。自动采集时间预算、TTL、缺票门控、312 策略和每次保存配置失效旧票的规则不变，不顺带采纳被拒绝建议。

## 功能变动

| 功能 | 变动前 | 变动后 / 入口 |
| --- | --- | --- |
| 手动采集 | 只能等自动后台轮次 | 账号管理勾选后“批量采集票据”，确认后执行；不改账号总开关或质量标签 |
| 历史 | 只读最近状态 | “采集历史”按批次查看，点击统计分类看结果、再展开逐次尝试；历史跨刷新保留 |
| 次数 | 固定最多十次 | 网关服务 → OpenAI → 票据采集的 max_attempts 接受可精确表示的正整数，取消十次业务上限；手动成功或终止性错误提前结束 |
| 合格长度 | 写死 292 | target_length 默认 292、可设 6–8192 字节；采集、缓存、调度、注入、状态统一判断；仍检查 HTTP 200/前缀/控制字符 |
| 每次日志 | 只有最近诊断 | 保存账号/邮箱、模型、目标长度、第几次、开始/结束/耗时、HTTP/头长度、固定原因、代理名称及参考 IP；不存敏感头正文 |
| IP | 不显示采集 IP | 有 HTTP 响应后用相同代理独立查询参考 IP，查询失败如实显示未获取，不改变采票结果 |

手动读取并冻结网关设置，不另设代理表单；已存在有效票不会先删除，失败不覆盖旧票。次数填 123 时最多尝试 123 次，非真正无限执行；前后端只保留整数可表示边界，巨大值仍可能长时间占资源。自动仍有每轮三十秒预算，不保证用满填写次数；界面明确区分。

## 开发逻辑与依据

入口验证明确确认、1–500 正整数账号（去重）、当前配置 revision 和原开关；不符合账号/模型资格明确跳过。每账号 Astra/Sol 分别成为任务，最多四 worker，复用原并发槽及 probeAttempt，写历史不调用质量测试逻辑。max_attempts 保持有限整数，避免先计算巨大总超时导致 duration 溢出；每次尝试仍有二十五秒超时，单个手动批次无三十秒总预算。第一次从现有代理记录选择，失败切换/固定行为沿原配置，成功停止，Retry-After 不绕过。

手动与自动共用 `round:<generation>` Redis owner 租约，最多等三十五秒让在途自动轮次自然结束，未获锁返回忙碌；本实例只允许一个手动批次。手动每十秒按 owner 续租四十五秒并更新历史心跳，丢锁/配置变化/关闭/停机/断连取消剩余任务。运行期间自动后台会因共用租约暂停派发，不能承诺大手动批次完全不影响其它账号续采。Close 使用一次释放和生命周期等待，旧 owner 不能释放新锁。已获票不回滚。

采集输出通过观察回调取得，自动调用不执行历史或 IP 请求。每次探测有 HTTP 响应后，通过既有 ProxyExitInfoProber、相同代理单独查询出口，最多四秒，仅保存解析通过的 IP；不传 OAuth 认证，不能把参考 IP 当成动态代理本次采票出口的证明。自动采集无新增 IP 流量。

历史单独 PostgreSQL 表，只保留脱敏配置/结果；发送队列八条、实时 UI 只保留最近五十条，不随轮数增长浏览器内存。每次日志先落库再 SSE，数据库失败取消并排空 worker，避免对每个剩余账号再次等待存储超时。最终结果保存后更新批次终态；SSE 缺 complete 不假装完成，单次写有截止时间。GET 只读分页；超过六十秒无心跳的运行显示 interrupted，不由 GET 修复/重播；重启不自动继续。
