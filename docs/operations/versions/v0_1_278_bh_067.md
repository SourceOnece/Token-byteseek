## 需求与范围

承接同一完整迁移，将账号管理状态流程与核心写SQL移到Provider模块。保留调用顺序、软删除、母子账号、旧DTO和票据/质量/调度边界；不先执行上游删列改表。

## 功能变动

| 范围 | 原来 | 本批实现 |
| --- | --- | --- |
| 删除/清错/手动调度 | AdminService内部直接编排 | `provider.Admin`拥有顺序与失败短路，旧服务委托后返回原完整账号DTO |
| 标错/清错/调度/删除基础写 | accountRepository内部构造Ent语句 | `provider/postgres.Store`执行同一语句/事务，写后原通知和缓存不变 |
| 管理运行阻断 | 旧AccountRuntimeBlocker | 窄适配器桥接到Provider RuntimeUnblocker，仍清同一阻断状态 |
| 旧SQL数据 | accounts、分组关联与测试计划 | 表/列不变，影子顺序和软删除保持；无生产删除 |

## 开发逻辑与依据

迁移采用上游`provider.Admin`与`provider/postgres`所有权结构，先定义状态操作窄接口。清错误的限流/模型/临时冷却必须依原顺序执行，任一步失败不执行后续解除；仅全部持久写成功后清运行阻断。删除先影子后母号，不改原分组/测试计划清理事务。

`admin_provider_adapter`只投影影子ID和运行阻断方法；不复制账户或创建新维护资源。旧GetByID继续补回代理/分组，防止原生Record尚不拥有完整Group类型时响应丢字段。手动调度只更新schedulable；标错仍置error并停调，清错只恢复active/清message，不直接开启调度。关联删除、原单号测试计划删除与Ent软删除复用原事务；已有外部事务时不提交，独立调用自行提交。

外层原仓储仍在数据库成功后按既有语义处理scheduler outbox/本地快照。包括关闭调度时立即更新快照、删除时失效、清错/标错时刷新；本批不改变原通知失败日志策略，也不把多次清错写入升级为全事务。票据与质量检测仍执行自己的原子结果/账号版本CAS，不调用这些管理员无条件操作替代它们。

| 文件 | 调用链 |
| --- | --- |
| service/admin_account.go、admin_provider_adapter.go | 旧管理入口→Provider状态服务→原AccountRepository窄能力→完整回读 |
| provider/admin.go | 影子先删、清错五步、成功后解除运行阻断，失败立即返回 |
| provider/postgres/state.go、repository/account_repo.go | 基础写/单号删除事务→原缓存和outbox |
| provider/admin_test.go | 注入每一步失败，验证不越过失败解除阻断/删除母号，不额外改调度 |
| repository/provider_migration_integration_test.go | 真PG验证soft-delete、错误状态/调度分离、外部事务回滚及原读适配 |

## 上游同步与保留差异
