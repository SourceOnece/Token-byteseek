## 需求与范围

将批量题目检测和定时检测从仅独立 Codex OAuth 扩展到 OpenAI API Key 上游，保留关键词判定、满血/降智/失败调度联动、结果历史和超时配置。定时计划新增管理员点击即可触发的立即执行入口；计划卡片外置绿色启用/暂停控件，保持启停确认和数据库租约约束。

不涉及 Claude、Gemini、DeepSeek 等其他平台，不改变用户网关 API、鉴权、计费、账号调度算法或 Metadata 逻辑。

## 开发逻辑与依据

1. `IsOpenAIQualityTestable` 统一服务端资格；仓储 SQL、Ent 质量过滤、统计和结果读取加入 `oauth/apikey`、非影子、非 Agent Identity 条件，避免前端筛选与后端 Count 分裂。
2. 请求新增 `api_protocol`。OAuth 固定 Responses；API Key 在显式选择时只走对应构造函数，未指定时兼容账号原协议。Chat 质量解析要求 index 0 的可见内容、`finish_reason=stop` 和 `[DONE]`，忽略 `reasoning_content`，响应错误、截断和断流均失败；普通连接测试保留旧解析器。
3. 计划新增 `manual_requested_at` 和轮次 `trigger_source`。立即执行只记录一次待执行标记，runner 的 `SKIP LOCKED` 领取后清零并创建 manual 轮次；暂停清除活动租约，提交结果仍受计划锁和运行来源保护。

## 包豪斯适配

## 接口数据与兼容性

新增可选字段 `api_protocol`、计划返回 `manual_requested_at`、轮次返回 `trigger_source`；新增管理员 POST 立即触发路由。新增迁移 `268_codex_quality_manual_trigger.sql`，仅给既有质量计划/轮次增加可空请求时间和默认来源字段，无用户接口、鉴权、计费或普通网关变化。旧计划缺少协议时按账号原配置兼容。
