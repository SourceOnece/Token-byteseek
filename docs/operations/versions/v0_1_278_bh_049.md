## 开发逻辑与依据

前序只读审查以临时 Go overlay 和 Vue 组件测试复现问题。本次把反例纳入仓库，保持原配置/凭据/账号资格CAS和独立票据键，避免用取消保护的方式消除竞态。

调度仓储返回UPDATE实际产生的updated_at，未修改时返回零时间。工作线程把该精确版本传给写库期间已到达的较新待处理信号；只接受相同数据库版本，不把seenAt向后移动，也不允许忽略另一次人工/质量检测写入。队列仍是有界、尽力处理，不承诺多实例全局可靠消息顺序。

手动租约内容只有批次ID和未完成账号ID，最多500个，不包含账号凭据。自动轮次仍用原round租约选一个实例，但逐号排除手动保留范围。每个账号最后一条模型结果落库后，CAS缩小保留范围；每10秒续租，旧owner不能覆盖/释放后来批次。手动与自动共享global-slot、account-slot、model-work短租约，任何部分未取得都先释放后等待，防止持有部分锁相互卡死。已在途自动请求不会被手动强行截断，手动取到模型槽后重新读退避，不能接着绕过该请求刚产生的限流。

双链路完成解析复用原错误分类，识别error.code/type与response.error.code/type。明确错误优先于“完整成功”判定，不发布候选票，模型不符和普通断流仍按原尝试配置处理。冷却早退出不继续占worker并伪造次数；任务保留最近实际attempt用于最终取消/跳过日志，但不把上一轮missing冒充新的跳过状态。

配置维护使用新鲜、可读快照；业务使用最后确认的配置辨别作用域，失联时范围内拒绝。首次启动还未确认任何设置时，独立OAuth先等设置读取；已确认关闭的总闸/账号和已知范围外模型仍按旧路径。读取恢复或成功保存恢复新鲜状态。该策略可能短暂503，目的是不把数据库故障当成管理员主动关闭双链路，不保证无故障可用性。
