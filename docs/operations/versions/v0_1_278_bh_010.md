## 开发逻辑与依据

所有新增行为置于已有 codex_metadata_repair_enabled 快照构造与应用链路；不改通用白名单或关闭分支。父线程/子代理的 body 内嵌当前值优先，再取 flat，再取首轮内嵌/独立头；后续 WS 不把旧握手回合关系覆盖新帧。选中的非法来源回退旧流程；多个不同有效来源按当前 body 优先，不扩散矛盾别名。

普通 off/device 的引用按既有账号 namespace 与 API Key ID 对同类型 thread/turn 做确定性隔离。session/full 会重生成部分身份，使用最多 32768 条、一小时有效期的进程内 LRU 映射，并按凭据 namespace、API Key、mode/seed/device 来源分区；只保存摘要键和出站 ID，不存 token/提示词。只有快照应用到出站 body 后才登记；相同 key 在期限内出现不同结果标记歧义，不采用最后写入值。没有可靠映射时省略可选关联，不指向其它账号。实际 previous_response_id、input、工具历史和调度粘性不改变。

Memory 的嵌套完整对象和 header 投影按官方省略 installation/session/thread/agent/window/window_number/context_window_id；已有 turn 仅按来源处理，不从 flat 或握手补造。flat 兼容字段仍遵守原账号隔离，不把 Memory 变成另一种业务请求。

关键调用：原 Forward/WS 入口准备快照 → Metadata 核心收集 lineage 和处理 Memory → lineage helper 按 namespace/映射生成可选关系 → 构造器及 WS payload 应用同一快照 → 只在 body 投影成功后登记对应主编号。WS pool 增加父线程/子代理字段，不改变账号选择或连接容量。
