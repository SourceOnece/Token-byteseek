## 需求与范围

用户已部署 `https://test.byteseek.ai/admin/accounts`，要求测试并为选中账号的批量编辑增加 metadata 配置，后补充模型必须使用 `gpt-6-astra`。本版不改 bh.003 的出站修复算法、不改 UI 整体风格、不替用户批量开启线上账号或替换容器。

## 功能变动

批量编辑新增“不修改 / 开启 / 关闭”三态字段，默认不修改。仅所选目标全部为 OpenAI OAuth/Setup Token 时可操作，混入 API Key/其它平台时不提交该项。关闭显式写 false，不能靠省略字段关闭旧 true；取消或重开恢复不修改状态。

## 开发逻辑与依据

复用已有自研 Select 和 `extra` 键级批量合并，使用唯一字段 `codex_metadata_repair_enabled`。不修改态不参加“有待更新字段”的判断、不构造 metadata extra；开启/关闭独立成为有效更新。前端显示与提交都校验目标类型，防止选择范围变化后残留草稿作用于错误账号。其它已选择编辑项仍按原逻辑合并提交。

筛选模式复用原 filters 入口，选择模式提交选中 ID；目标类型/筛选条件改变时只重置本字段为不修改。默认不从现有账号多数值推断批量意图，避免误改少数账号。自研 Select 的名称/说明通过组件支持的 ARIA 属性传到实际按钮。

- [BulkEditAccountModal.vue](../../../frontend/src/components/account/BulkEditAccountModal.vue)：目标资格、三态选择、有效更新判断、payload 构造及重置。
- [批量组件测试](../../../frontend/src/components/account/__tests__/BulkEditAccountModal.spec.ts)：未修改不写、开关单独提交、混选/未知类型、重开和筛选范围变化。
- [管理服务批量测试](../../../backend/internal/service/admin_service_bulk_update_test.go)：原接口向 repository 传递准确 ID 和 true/false 补丁；未修改后端生产逻辑。
