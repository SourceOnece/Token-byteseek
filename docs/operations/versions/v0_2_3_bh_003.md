# v0.2.3-bh.003：修复创作台 OAuth 图片调用

## 元数据

2026-10-03 Asia/Taipei，源码验证完成，镜像待构建，未部署。前版 [v0.2.3-bh.002](v0_2_3_bh_002.md)，B0 为 `405b6ccec`，源码 VERSION 为 0.2.3。发布构建版本为 0.2.3-bh.003。

## 需求与范围

用户报告创作台 `creative platform rejected request`，要求 OAuth 号池与 API Key 均可生图。代码检查发现创作台允许选择 OAuth，但执行时仍发送标准 API 图片请求，Codex 图片转换器仅接在网关和后台测试入口。本文记录该接线修复，普通上游新增功能另行同步。

## 功能变动

| 入口 | 变更前 | 变更后 |
| --- | --- | --- |
| OAuth 创作任务 | 取 OAuth token 后请求 api.openai.com 图片端点 | 按账号类型调用 Codex 图片端点或 Responses 图片工具 |
| 文生图/编辑/局部重绘 | 创作台参数采用标准 API 格式 | OAuth 转为共享图片输入，传递源图与 mask；API Key 继续 JSON/multipart |
| 原生端点兼容 | 创作台未使用 Codex 回退流程 | 原生端点 404/405 时，同一账号尝试一次 Responses 工具 |
| 结果与错误 | OAuth 无专用响应解析 | 复用直接图片 JSON 与 Responses 图片解析；上游错误继续脱敏，结果损坏结束任务 |

## 开发逻辑与依据

`CreativeTargets.ForProvider` 按已选账号类型设置 `OpenAIOptions.OAuth`。`ExecuteOpenAI` 在 OAuth 时调用专用函数，API Key 使用现有地址和参数构造。任务选组、选号、资金预占、单张结果保存和结算仍由 creative worker 执行。

OAuth 请求复用 `BuildImagesOAuthPayload`。Image 1.5/2/2.5 走 Codex Images JSON，Image 1 走 Responses 图片工具。404/405 才触发一次协议回退，401/403/429/5xx 交给现有错误与任务重试规则。成功响应读取上限为 64 MiB，错误体上限为 2 MiB；HTTP 成功后读取/解码失败标为结果错误，worker 结束本次任务。

请求认证从当前提供商或影子账号母账号读取。任务会话先按用户、托管 Key、run ID 和提供商命名空间隔离，再应用账号已有的指纹模式；full 等模式仍按管理员配置执行收敛。影子账号解析一次母账号后，将该记录交给认证与身份头构造。代理、TLS 模板/路由及 User-Agent 使用账号配置和网关技术组件。后台请求从任务数据构造头部。

| 文件 | 职责 |
| --- | --- |
| `creative/provider/openai.go`、`openai_oauth.go`、`target.go` | 两种认证分派、请求转换与结果处理 |
| `gateway/provider/creative_targets.go`、`creative_oauth_request.go` | 账号、认证、TLS 与任务会话 |
| `app/creative_targets.go` | 注入当前提供商读取与客户端配置 |
| `tools/architecture/catalog.go` | 允许 creative 的平台适配调用共享 OpenAI 图片实现 |

## 风险与后续同步保留点

创作台、公开图片网关和后台单号测试是三个入口，后续同步需要分别检查实际执行路径。普通 Key 生图测试通过不能证明 OAuth 创作任务已接通。上游模型权限、代理连通性与内容政策仍可拒绝请求，错误码用于区分这些情况。
