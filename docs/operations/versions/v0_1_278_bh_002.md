## 开发逻辑与依据

### 当前规则与历史事实分层

AGENTS.md 放不可跳过的门禁；运维专题说明当前流程和设计契约；`versions/` 放每次交付的历史事实与原因。根目录路由到运维目录，再进入规则和版本索引，避免把越来越长的历史堆进 AGENTS 或 README。历史记录不替代当前接口/架构文档，现行契约变化仍同步原专题。

### 编号与记录颗粒度

一次有目的的交付而非每次编辑对应一个 fork 修订；上游版本不变也递增序号，因此小修和纯文档变动可独立定位。保留应用真实 VERSION 和 Git tag 的意义，文档编号不伪装成软件版本。规则从本次开始执行，补录已核实的 v0.1.278 发布作为 .001，本次治理作为 .002；更早资料有证据后才能补录。

### 开发逻辑不等于 commit 摘要

模板要求变动前后行为、关键模块/调用或状态关系、为何选此方案、异常与回退、兼容性、测试和限制。用相对文件链接与 SHA 连接到实际代码，不能只写“优化”或堆文件名；未改内容仍须说明不涉及原因。变更范围大时按功能拆段，不要求复制整仓库，也不保存私人推演或全部调试流水账。

### 防止发布证据循环

源码提交应含当时已知的变更和验证记录，但自身提交 SHA 和远端 digest 只有事后可知。允许在同一版本追加纯文档发布证据，不再创建一版、循环 amend 或重打镜像。应用交付仍要验证后推送两个标签；纯文档交付只校验和提交文档，最近应用镜像保持不变。上线状态单列，避免“已推镜像”被误当作“已部署”。
