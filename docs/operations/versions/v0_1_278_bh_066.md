## 开发逻辑与依据

原账号GetByID/GetByIDs同时处理基础读取和关系补全，整体挪动会把尚未迁移的Group/价卡循环依赖带入Provider。先迁基础记录与查询，旧组关联补全保持；相同账号、模型、凭据、业务代理与时间字段不得遗漏。原子创建、调度CAS/outbox和额度写入在迁移前保持原实现。

`provider.Record` 是内部核心投影，明确隐藏 Credentials/Extra/Proxy；`egress.Proxy` 成为代理基础类型，service.Proxy 仅保留别名。Provider PostgreSQL Store 目前故意读取原 `accounts` Ent 表，不新建连接、不改变软删除；旧 AccountRepository 的 GetByID/GetByIDs/Create 通过 Store 后，再调用原分组/代理回退补全。`ProviderRecord`/`AccountFromProviderRecord` 用于新旧链路往返，ParentAccountID→ParentProviderID、QuotaDimension、凭据和时间字段均保留。

创建路径仍由旧 AccountRepository 持有事务：Provider Store 只写核心行并回填 ID/时间，不提交事务、不写分组/outbox/票据；调用方继续在同一事务里完成票据配置、分组关系和调度事件。不存在记录仍翻译为 `ACCOUNT_NOT_FOUND`，批量读取保持首见顺序、去重并忽略缺失 ID。
