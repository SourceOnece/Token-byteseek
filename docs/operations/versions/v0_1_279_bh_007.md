## 开发逻辑与依据

### Key 与账号边界

`apikey.RotateCredential` 先验证归属及团队上下文，系统托管 Key 不开放轮换。仓储用 ID、用户、旧凭据和未删除条件原子替换，仅更新 key/updated_at；并发轮换、删除或托管状态变化返回冲突。提交后用独立 5 秒上下文清理新旧认证缓存；既有数据库触发器继续写失效 outbox，避免网络通知失败造成永久旧缓存。已进入的请求不主动断开。

创建频率只在校验通过后累加操作成员计数，团队付款人不借用成员窗口；固定 Redis 窗口首次写 TTL，后续创建不延长。删除和改状态均不重置计数。存储失败也不返还已计入次数；Redis 故障沿用原防滥用放行策略。数量上限保留 TokenFlux 的用户行锁事务实现，比再加一层非原子“先数后写”更可靠。

配置 `api_key_create.max_per_user_per_hour` / `API_KEY_CREATE_MAX_PER_USER_PER_HOUR` 默认 60，0 关闭，负数启动校验拒绝，修改后重启。数量上限仍在后台用户管理，轮换不算创建。

### 属性与价格隔离

`modelcatalog` 只解析展示目录；`routing.ModelAttributeService` 按可请求结果的最终模型匹配属性规则，先精确、再有序末尾通配符。缺字段继承，false 和空模态是明确值。一组最多关联一个属性配置，一份配置可关联多组；冲突由数据库唯一约束和事务防止。

属性不用于选号、协议准入、请求参数覆盖、STATE、质量判断或计费。展示中不同路线取共同能力和已知最小上限，并标明差异。仅 OpenCode 导出其 schema 支持的属性，缺 context/output 任一个时不生成 limit；Codex 配置及黑底正文不加入未知参数。

默认 `pricing.catalog_format=legacy`：原价格源、hash、fallback/override、未知模型回退保持。属性从内嵌 models.dev 快照加载，管理员刷新属性只更新内存属性，不改价格，重启恢复内嵌版；管理覆盖档案保存在数据库，不受重启影响。

显式使用新价格源需同时设置：

```yaml
pricing:
  catalog_format: models_dev
  remote_url: https://models.dev/catalog.json
  hash_url: ""
  fallback_file: ./resources/model-pricing/model_pricing_supplements.json
```

切换前须核对报价，models.dev 的报价可能与旧源不同。自定义覆盖继续最高优先级；格式支持供应商身份、上下文绝对阶梯、Fast 显式零价和缓存桶。旧价格模式的查询被明确隔离，不因加载展示属性而改变计费候选。

### Codex 兼容

GPT-6.1 Sol 使用 sub2api 固定目录的基础指令文本；不引入其完整 manifest 服务。Responses/Chat/Messages 和 WS 的公共推理校验拒绝该模型显式 none/minimal/disabled thinking，避免转换静默升档；已支持 low/medium/high/xhigh/max，Ultra 仍是客户端模式而非上游 effort。

专属回退输入/输出为 2/10 USD 每百万 token，Fast 为 4/20，缓存写入 2.5、读取 0.1；超过 272000 输入 token 时输入/输出倍率为 2/1.5。管理员显式价卡仍优先。Astra ultrafast 模型专属 6 倍来自本批 sub2api 行为，不改变其它模型的 Fast 策略、分组免费 Fast 或历史账单。
