## 需求与范围

## 功能变动

TokenFlux 本批包括删除 API Key 后的在途结算、WS 每轮鉴权、上游响应模型全协议采集与管理展示、Responses 非标准终态兼容、批量操作栏、创作台、用量/审计、品牌图标及深色引导修正。sub2api 去重后补入匿名订单查询限流、邮件验证码原子尝试计数、密码重置摘要/一次消费、Antigravity 错误脱敏及错误码说明纠正。

| 功能 | 变更前 | 变更后与入口 |
| --- | --- | --- |
| 在途结算 | 删除 Key 可使已发生消费的 Key 更新条件不匹配 | 已通过鉴权的消费仍结算；新请求拒绝已删除 Key，WS 每轮重新验证 |
| 响应模型 | ByteSeek 已有管理员 response_model；部分转换依赖旧旁观器 | TokenFlux 原始观测覆盖更多协议/平台，新增差异字段和管理员导出；旧字段兼容，只展示一份差异 |
| Responses 终态 | 部分中转返回裸 Response 或 response.done 时无法标准结束 | 包装并标准化明确状态，重复成功终态不重复输出；失败/未知状态不伪装完成 |
| 提供商批量栏 | 多个操作全部平铺 | 选中后显示独立栏，低频项进更多；按筛选批改在工具菜单；保留题目检测和采集按钮 |
| 创作台 | 工具、输入、历史浮层配方分散 | 统一画布浮层、模型/参数面板与状态行，两主题使用同一逻辑 |
| 展示 | 部分用量标签窄屏冗长、引导暗色对比不足 | 用量统计共用小标签；审计搜索、分布表、头像、模型/品牌图标和深色引导跟进 |
| 匿名订单查询 | 无专属 IP 窗口 | 原 verify 入口每 IP 每分钟 20 次；Redis 故障放行，签名恢复和支付回调不受影响 |
| 邮件校验 | 并发错误尝试读改写可能覆盖；重置原文可重复校验再删除 | 先原子预占验证码次数；重置仅存 SHA-256，原子比较删除；重发生成新链接 |
| Antigravity 错误 | Gemini 原始错误体可能包含账号项目身份 | 客户端只收 code/status/脱敏 message，丢弃 details；诊断/重试仍使用原观测 |

## 开发逻辑与依据

按上次实际功能基线 d81377f19 对本地主体进行三方差异合并，不使用更早共同祖先重放已适配的功能。响应模型新链与 ByteSeek 原字段及票据守护去重接入，管理员可见范围保持。批量栏需保留题目检测/手动采集入口；新创作台控件跟随两套皮肤。

- `protocol.ResponseModelObserver` 负责原始模型声明，终态优先；各平台执行器与转换器传入结果，完成快照冻结本轮字段。`recordedResponseModel` 优先新观测，旧图片/定制链的 ResponseModel 兜底；新日志同时写新旧字段，避免并列的两套展示。历史旧字段保留，不从请求型号回填虚假的历史响应。
- 管理 DTO 增加 upstream_response_model/upstream_model_mismatch，普通用户 DTO 不含新旧内部模型。管理员表格保留请求→路由→响应布局，相同不展示，CSV 增加两列。布尔空值表示未观测，不误写为“相同”。
- WS 重新鉴权与在途结算采用 TokenFlux 实现。ByteSeek 的票据注入仍经过 SendWithTLS，不能在解决文本冲突时换成原始 Transport.DoWithTLS 绕开票据。模型观察按尝试/turn 重置，票据复验旁观对象仍独立。
- 票据候选/复验/业务守护读取同一 Responses 终态规范化副本，以识别上游新增的明确成功 done/裸终态；不修改业务流字节，不放宽缺状态、失败、合格长度、模型匹配、双链路或调度规则。
- 标准 Responses SSE 保留 TokenFlux 的末尾补充用量读取；ByteSeek 原第一帧完成立即返回与新重复终态冲突，会把 9 个输出 Token 记成 3。最终改为成功终态后最多一秒 drain，正常 EOF 立即结束，补充用量仍解析、重复完成不下发；上游不关闭连接也不继续等几十秒。失败/缺终态沿原规则；一秒之后才补报的数据不承诺收取，属于保留旧防挂起行为的明确边界。
- 新 usage 迁移映射为 292，原 response_model 及历史迁移不删除。Ent 与 Wire 由生成器重建，SQL 批量插入/查询及参数类型表一起适配，真实存储测试需验证三个字段。
- 邮件缓存沿现有 identity 所有权适配：验证码计数与剩余 TTL 在 Redis 脚本中处理；通知邮箱共用次数规则；新 reset token 只有原文进入邮件，缓存保存摘要，消费失败不会继续改密码。发信冷却保持原值，重发会使旧链接失效，升级前旧明文缓存不再接受，用户需重新申请链接。
- 订单限流复用 app 注入的固定窗口限流器及既有可信 IP 解析；不另建 Redis 客户端。Antigravity 脱敏在最终客户端输出边界执行，保留上游错误供原健康/故障切换和管理员日志处理。
