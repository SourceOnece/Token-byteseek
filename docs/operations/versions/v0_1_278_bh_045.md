## 需求与范围

用户指定账号级控制与批量编辑、守护状态展示、账号级动态采集代理（未配置回退网关设置），并选择借鉴适合当前号池的逻辑；随后明确确认“默认只观察记录，自动废票重采可选且默认关闭”。保留包豪斯、现有多模型/自定义长度/多代理/手动日志、加密Redis、集群租约和既有会话/计费边界。不恢复Metadata实验，不修改普通业务代理，不强制WS桥接。本版不新增固定业务代理复验或严格采集模型验证，不改变原合格票据接受条件。

## 开发逻辑与依据

采用本地票据服务适配，不复制STATE Kit整文件。实现重点如下：

1. 私有配置`codex_ticket_runtime.accounts`按ID保存mode、账号revision、代理密文和守护模式。`ticketConfigForAccount`只生成当次有效副本，总闸优先；账号没配置保持原键兼容，有覆盖时把该号revision加入原隔离代次。编辑一号不使全池换代，全球保存沿原规则使旧代次退出。普通账号对象/extra/导出不增加这些敏感字段。
2. 账号GET只返回是否配置和来源，不回显URL或密文。PUT仅接受明确patch字段，重复ID去重；不存在/影子/AgentIdentity/API Key等任何不适用账号使整批拒绝。单号revision检查防旧表单，底层设置仓储再以完整旧JSON做数据库CAS，防止多实例同时更新不同账号丢数据。冲突返回固定安全提示，不自动重试；测试替身用原进程锁，不作为生产CAS替代。无需数据库迁移。
3. 自动probe、手动collect、Blocks、Apply和Status全部解析同一有效账号配置；初筛不从精简账号摘要找覆盖字段。账号off不执行采集/门控/注入；未配置代理沿全局固定或失败轮换。动态代理不直接改变业务IP；每次合成尝试对认证占位符展开一个随机ID，手动参考IP查询共用该次地址，密码仅内存使用且不写历史。配置变更后的旧任务在尝试前/发布前被代次挡住。
4. `ApplyRequest/applyWithReceipt`在确实注入票据后生成内部收据，绑定同账号/模型/配置/凭据键与准确密文。HTTP/SSE/JSON响应只有2xx、合法长度信号或成功完整终态模型不符才记录；解析器上限单事件/JSON 1MiB，不提前读、不改原始字节/错误，缺字段/损坏/未完成不当异常证据。模型按最终出站精确ID比较，观察的是声明不是能力证明。
5. 原生WS保留既有ctx_pool/passthrough，不改成HTTP Bridge。收据存物理连接，复用不能拿新Acquire收据冒充旧握手；真正重连时校验发送头与收据状态哈希，若已被原回合状态逻辑替换就不绑定。握手只观察当次返回头；完整帧只观察与收据相同的最终模型。保存后旧连接不会被强制断开，收据代次过期后不继续触发，详见限制。
6. Redis Lua在单次操作内比较票据密文是否仍为当前值，才写脱敏守护摘要或删除：旧请求晚到时绝不能删除后来新票。相邻同票/同原因去重，摘要24小时，不含正文/票据/URL。observe只记录；recover_length/recover_model/recover按选项废票，重采由原四worker、集群租约、轮次预算及Retry-After保护执行。唤醒标志不被在途轮次结束覆盖；手动批次占锁期间等待，不启动另一个无界队列。
7. 守护记录不是质量检测；模型当前可用性与历史异常分开。新状态通过已有分页账号批量状态GET返回，每个模型多读一个Redis键。Redis记录单次150ms预算，故障不让业务响应失败，也不谎称成功删除；同步观察有小幅延迟风险，没有生产压测结论。

## 发布部署与回退

bh.045固定标签预检不存在；验证后构建linux/amd64镜像，先推固定`0.1.278-bh.045`再同步latest/bauhaus同产物，提交/digest事后追加。当前未构建/推送/部署，不自动替换生产。

已有账户不需重新导入，旧票在未改配置和凭据时沿用。账号首次保存/修改只使该号票据换代，全球保存仍使全池换代，可能短暂无票；保存风险在界面直接展示。回退前先用新版本关闭票据总开关，备份加密设置；再回退bh.044镜像`sha256:59202d54d68121b0f409ede96a3ab621a8a5209b30eb6396ad9ef9c6911a66a8`，不要在旧版开启总闸并以为账号off仍有效。无新数据库迁移，守护摘要TTL自动清理，不删除历史数据。

## 风险与后续同步保留点

异常长度及模型字段不是模型质量证明，精确模型名可能因合法别名/快照名称变化而不同；先观察记录再决定开恢复。恢复会产生对应模型缺票窗口，所有账号均无有效票时503仍可能发生。未强制业务代理复验或改变原获票门槛，所以“新票”不保证业务响应一定符合期望；反复异常会继续受现有轮次预算/重试/Retry-After限制，管理员可关闭恢复，不承诺绝无上游过载。

Redis记录每次150ms预算、状态多一个MGET键，设置accounts映射每两秒读取，特别大的池需实测延迟/配置体积。账号覆盖只有单条自定义动态代理，未新增每账号多代理列表；没有覆盖才继承全局多代理轮换。仅批量选中ID1–500，不在本次实现筛选条件无限更新。

原生WS保持连接复用，注入和STATE响应头只存在握手。轮中模型不同/回合状态取代原票据的重新握手，不使用错误收据去废票；可能无法观察全部上游变化。全局/账号变化两秒轮询传播，跨实例极短在途窗口不等于强制事务隔离；新键确保旧结果不写成新配置票据。守护信号记录失败不影响业务，也意味着不能保证每次异常都持久化。账号删除后私有配置映射暂不自动清理，ID不回收时不作用于新账号，未来维护须保留加密和作用域。

后续同步必须保留默认只观察、相邻信号去重、原子比较实际票据、凭据/模型隔离、配置CAS、bh.044有界换号、原生WS/用户会话归属、手动停调采集例外与包豪斯。不能恢复Metadata、无界采集并发或第三方插件强制传输来绕过这些契约。
