## 开发逻辑与依据

改前审计已确认 bh.010 的测试把 subagent_kind 错误写为 collab_spawn，未覆盖官方 thread_spawn 组合；缺少当前 self-root 与 Memory self-root、失败构造登记、子先父后、跨进程/一小时后重建等场景。官方代码依据为本地核对的 openai/codex 提交 52e12e0cb506e7bb2c9e406fc84d922e274a0e40；OpenAI Docs 检索服务返回 502，不宣称已经得到在线官方验收。

本次删除进程 LRU 及 applyRaw/applyMap 登记行为，不再让请求是否成功/先后顺序/其他用户容量影响元数据编号。沿用原 scopeCodexAccountIdentityValue，以凭据 namespace、平台 API Key、字段类型和原始值派生 UUID；主 thread/turn 及父/根/分叉引用同源。自引用立即匹配，不需要先发送父请求。这只是编号变换，不代表被引用请求已成功，也不会赋予跨账号的 response 访问能力。

修复快照仍位于原显式开关门禁之后，先收集原始 metadata，再执行旧身份/指纹处理，最后以确定性 thread/turn/window 覆盖快照内部的随机/合并值，HTTP 与 WS body 共用；原 fingerprint 文件和 root prompt_cache_key 未改。安装设备与 session 收敛继续生效，但开启修复的 session/full 不再将有来源的不同线程合并，也不为显式 turn 每次重新生成随机编号。无 thread 时仅在收敛模式从已有 session 推导，无任何来源时不造 thread，使用隔离的本请求 turn/追踪号保证未知线程不跨用户共享连接。没有显式 turn 的普通请求仍生成一次请求 ID，内部重试复用；Memory 不补造 turn。这个取舍已在实施前向用户说明，不能声称所有指纹出站编号完全未变。

内嵌 subagent_kind 和 flat/独立 x-openai-subagent 分别收集，不覆盖各自合法值；只有缺少兼容值时才将 thread_spawn→collab_spawn、review/compact/memory_consolidation→同名投影。独立头可能来自 Internal 来源，不能反向补造内层 kind。未知扩展独立保留。非法可选 lineage 只省略该字段，兼容 metadata 头非法/超限只忽略这个来源；主身份、完整 body 非法和缺少可靠 namespace 仍回退旧路径，不修复无法安全解释的数据。

WS 有效修复快照已把完整元数据放进每轮 response.create，因而握手省略 x-codex-turn-metadata、x-codex-parent-thread-id、x-openai-subagent 三个请求级兼容头，池兼容键撤销 bh.010 的父线程/子任务比较。实际账号、安装/会话/线程/窗口、原追踪兜底、beta/TLS 和开关隔离保留；握手不再冻结首轮父子关系。HTTP 的三个兼容头继续存在。关闭或无有效快照时不执行 WS 头省略；未修改连接容量、实际 continuation、错误分类或失败重试。

分组准入在路由层执行，Messages handler 内还有同一集合检查；服务层 Metadata 不拥有分组开关。三类入口原来的模型/推理/Fast/工具/缓存转换先后顺序保持，Metadata 只写 client_metadata 和自己的出站头；额度失败继续由 handler 选择下一个账号。假上游额度测试只验证选中及发送到下一账号，不把测试写成真实上游接受、缓存命中率或模型质量保证。

## 风险与后续同步保留点

不得把本地协议回归写为真实 overloaded 已解决。跨账号切换仍受原有流输出及工具上下文可重放约束，不能把元数据编号当成跨账号访问能力。父子若使用不同平台 API Key 或凭据来源，按边界隔离，不强行串联。

升级后开启侧线程编号及 WS 兼容头投影会变化，需新建会话；同凭据共享同一个平台 API Key 的多个最终用户仍无法仅靠该 Key 区分，需要上层分配独立 Key。不改真正的 prompt cache 参数不代表能保证上游缓存命中率不变。WS 不发送可选请求级兼容头的接受率、真实 overloaded、真实多实例长时间压测仍未验证。未来同步不得恢复随机关联缓存、混淆子任务字段或放宽关闭侧行为。
