## 开发逻辑与依据

`readStorageWithLegacyKey` 捕获存储读取及迁移写入异常；语言与协议同意的主键仍为 ByteSeek 原键，避免覆盖现有偏好。协议撤回写入 `{}` 阻止跨品牌兜底复活旧确认。初始化回归直接导入 i18n，不能只测未接线的工具函数。

安装器采用 TokenFlux `detect_existing_installation` 和默认升级流程。首次安装使用 `/opt/sub2api`，已有 `/opt/tokenrouter` 则继续使用该目录和服务用户/组，同时发现两套实例时返回冲突。发布源默认 `SourceOnece/Token-byteseek`，可通过 `BYTESEEK_RELEASE_REPO` 指定其他仓库。下载依次尝试 byteseek/tokenrouter/sub2api 归档和二进制名。发布版本查询失败时，升级在停止服务之前退出。测试使用临时根目录、本地归档及 curl/systemctl 替身。

通知在 Release 产物和版本回写成功后运行，只使用本 fork Secret `DISCORD_RELEASE_WEBHOOK_URL`；显示品牌改为 ByteSeek。保留目标域名校验、禁止 mention、UTF-16 长度约束、回执校验和日志脱敏，网络失败不自动重复发消息。

流式读取继续采用 TokenFlux 唯一解析器与终态去重，票据旁观/注入和完成计费链保持。删除额外一秒计时器，保留已有空闲计时；明确成功后到达空闲期限走 finalize 而非 StreamTimeout，避免已经成功却关闭调度。管理员把空闲期限设为 0 时沿原配置禁用该期限，依赖请求取消/传输关闭，不暗中新增上限。迟到用量用 1.2 秒间隔回归，另验证不 EOF 时按配置收尾。
