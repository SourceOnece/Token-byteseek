# 近期更新、配置位置与双上游差异说明

本说明按 2026-10-01 核查的代码编写，覆盖最近从 TokenFlux 0.1.279 主线更新到 0.2.0，以及 ByteSeek 0.2.0-bh.001～bh.005 的变化。它说明“现在实际有什么”，不是把上游更新公告当成已经上线的功能。镜像发布和服务器升级是两件事，服务器当前版本以实际运行镜像为准。

## 先看这次修正

bh.005 有两类变化：你的首页/排行展示修正，以及 TokenFlux 六项通用更新和导入兼容补齐。没有改票据/质量判定和计费算法；分组可用性探针的模型映射与候选、模型属性回填以及图表比例确有修正，不能把整批都说成纯 UI。

| 位置 | 包豪斯 | TokenFlux |
| --- | --- | --- |
| `/home` | 你原来的不对称首屏、三元素轨道、文字走马灯和色块卡片 | 使用同一份结构和模板，只换成 TokenFlux 品牌青、圆角和轻描边，不再使用上游独立首页 |
| 首页走马灯 | 中文九词，切英文才显示英文；包豪斯黑底多色字 | 同一组文字和滚动结构，使用 TokenFlux 深青底和浅色字 |
| 用量排行榜顶部 | 从左到右第 1、2、3 名，红、黄、蓝；左上 `#1/#2/#3` 黑字白底，右上三角形/方形/圆形白色 | 保留第二、第一、第三的领奖台排列和上游颜色 |
| 下方排行榜 | 前三名横条恢复浅红/浅黄/浅蓝，小编号框仍白底，数值按名次突出 | 保留 TokenFlux 浅色行背景及原样式 |
| 头像菜单 | 移除内置 GitHub 地址和图标，保留资料、客服、导航等现有功能 | 同样移除这个内置仓库入口 |
| 公共下拉框、弹窗关闭、分页、筛选 | 直角、硬阴影、包豪斯重点色 | 回到 TokenFlux 自己的控件外观，不再被包豪斯样式串入 |

首页两种呈现共用同一份市场、统计、精选模型、登录状态和页脚配置，没有两套接口。后台配置了自定义 HTML/URL 首页时，自定义内容仍优先。原有顶部账户菜单、客服和登录流程继续使用当前公共组件。

前一版排行并非把“第 1 名”设成了黄色，而是沿用了上游“第 2 名放最左边”的顺序，因此左边第一张看起来是黄色。这次只在包豪斯改为顺序排列。

## 近期已经同步的功能

bh.005 修正：旧首页的 home.features.multiAccount 已改为当前 multiProvider 键，中文显示“稳定可靠”，英文 Always Reliable，说明表达多提供商智能调度。上一版测试用 key 作为假翻译掩盖了缺失，本版增加真实中英文词典渲染及全部首页静态 key 检查。首页 LIVE ROUTE 示例改为当前市场/精选模型，不再写死旧 GPT-5.4。

本次新补齐 TokenFlux 六提交：分组探针正确传递映射后模型、分组模型候选使用真实可请求交集、歧义裸名公共属性回退、属性编辑自动填入已知资料、图表按真实比例绘制、标签辨识度，以及同链测试修正。属性配置入口不变，添加一个精确模型且属性为空时自动填充；手工填过的不覆盖。分组探针填写请求模型，修改分组规则后需保存再刷新候选；不用为该修复增加新开关。

额外补齐同版本 TokenFlux 导出文件导入：前端原本已接受 tokenrouter-data，但后端只接受 sub2api-data；现在两者 version=2 都可读。本地导出标识不变，旧 accounts 集合、错误版本和缺必填集合仍拒绝。

## 配置怎么填

### 1. 站点主题与首页

到管理员“系统设置 → 通用设置 → 站点设置”，选择“界面主题”，再点页面原来的“保存设置”。

- TokenFlux：默认上游风格。
- 包豪斯：你的纸色、红黄蓝、三元素、硬阴影；这次首页也恢复旧构成。
- 用户没有风格选择器。浅色/深色/跟随系统是另一项设置，仍可独立使用。
- 已打开的用户页面不会被强制刷新，刷新或重新打开后跟随站点配置。以前浏览器保存的 `visual-theme` 不再生效。

首页标题/副标题、精选模型、页脚链接依然在“通用设置”的原有配置区。改主题不会重置它们。填了自定义首页 HTML 或 URL 时，显示自定义内容；想看到内置首页，需要自行清空该自定义内容并保存。

### 2. 想获取最新模型，分清三种按钮

| 你想做什么 | 正确入口 | 能做到什么，不能做到什么 |
| --- | --- | --- |
| 更新目录里的价格/能力资料 | 模型管理 → 价格管理 → 网关默认价格 → 更新目录；属性页也读取同一目录 | 刷新目录资料，不修改某账号的真实权限 |
| 查询这个账号的上游返回哪些模型 | 提供商管理 → 新增/编辑 → 模型范围中的“同步上游模型”（满足平台/凭据条件时出现） | 向该账号上游查询并加入白名单草稿，仍需保存；上游不提供模型列表时可能不支持/无结果 |
| 快速填入软件内置型号 | 提供商模型范围的“填入相关模型” | 本地预设，不是实时远程查询，不保证账号能用 |

旧价格配置页面的“批量填入全部目录模型”已随 TokenFlux 删除。删除的是这个重复入口，不能理解成“整个项目不能更新模型了”。远程 Codex 完整 manifest 又是另一套能力，当前没有恢复，见未同步表。

### 3. 模型白名单和模型映射

白名单决定“允许哪些模型”；映射决定“用户写 A，真正发给上游 B”。两者不是一回事。

模型选择/标签控件逐个输入完整模型 ID 后回车，例如先输入 `gpt-6-astra` 回车，再输入 `gpt-6.1-sol` 回车。最终应显示两个独立标签。批量输入按该控件现有提示操作，最稳妥是“一行一个完整 ID”，不要把 JSON、`model=` 或自然语言描述填进去。

例如用户仍用旧别名 `my-codex`，你希望调用 `gpt-6.1-sol`，在相应层级模型映射中明确填 `my-codex → gpt-6.1-sol`，并核对分组准入、提供商模型范围。不要期望随意添加 `-max`、日期或供应商前缀就自动等于原模型。价格规则也使用完整模型身份，别名应核对实际计费模型。

### 4. 价格与 Max 推理倍率

到“模型管理 → 价格管理 → 价格配置 → 新建/编辑”，打开某条模型价格，选择 token 计费，在倍率区可看到 Fast、Flex、Max 推理倍率（仅在支持该倍率编辑的价格条目中出现）。

“Max 推理倍率”是收费倍率：例如基础价格是 1、该倍率填 2，命中对应 Max 推理计价条件时按规则变成 2。它不会把普通请求自动调成 Max，也不会强制让账号满血。请求的思考等级仍由客户端请求/已有思考映射决定。

设为显式 0 的单价代表免费，留空代表继承/未提供，不是同一个意思。未找到价格会显示未定价，不能假定免费。价格配置、分组/用户倍率、Fast 免费策略和提供商成本要分别核对。

### 5. 旧价格文件的变化最需要注意

当前采用 TokenFlux 新目录体系：

| 设置 | 现在怎么处理 | 你要做什么 |
| --- | --- | --- |
| `pricing.override_file` | 已退役，非空会警告并忽略，不再强制覆盖目录 | 若以前靠这个文件给用户定价，把售价迁入后台“价格配置”并关联分组；若文件还承担上游成本，要另配提供商成本规则 |
| `pricing.remote_url` | 默认 models.dev 目录来源；自定义源必须符合当前格式 | 普通部署可沿默认；自建源需检查格式，不要直接塞旧格式的价格 JSON |
| `pricing.check_interval_minutes` | 默认 10 分钟检查目录 | 不需要网页按钮；通过服务器配置调整，随服务配置加载 |
| `pricing.fallback_file` | 默认空，程序有内嵌补充；自定义文件仍用于补缺 | 补缺不能覆盖目录明确提供的值，包括 0；不能当旧 override 用 |
| 旧 `catalog_format`、hash URL/小时轮询 | 旧的双价格模式已退役，不能用来切回旧链路 | 新部署按当前配置示例；不要照历史 bh.007 的过渡方案重新开启旧模式 |

例如你以前给某模型在文件里写了低于目录的售价，升级后不能以为它还生效；应先在后台价卡里明确保存售价。此次 bh.004 不再改定价算法，这里是在解释前几轮已经发生的变化。

### 6. Key 创建数量和频率不是同一个限制

用户级“最多保存多少把 Key”在后台用户配置里；“一小时允许创建多少次”是服务器配置：`api_key_create.max_per_user_per_hour` 或环境变量 `API_KEY_CREATE_MAX_PER_USER_PER_HOUR`，默认 60，填 0 关闭频率限制，修改后重启生效。轮换已有 Key 不算创建新 Key。

### 7. 排行榜、属性和首页展示

- 系统设置 → 通用设置 → 用量排行：控制是否展示、显示数量、主排序指标以及请求数/Token/消耗等可见字段。两种皮肤读同一配置，隐藏某项后不会为了配色重新显示。
- 模型管理 → 属性管理：一份属性配置可关联多个组，一个组最多关联一份；未填字段沿目录，显式 false 表示明确关闭该展示能力。它不替代提供商协议/白名单。
- 系统设置 → 通用设置 → 首页模型展示：配置想展示的模型 ID；只显示市场里能解析到的条目，不能用此处创建不存在的模型。

## 你的定制功能保留了什么

这些大部分不是最近才新增，而是升级 TokenFlux 时必须保住的功能。

| 定制 | 当前入口/作用 | 本次影响 |
| --- | --- | --- |
| Codex 票据工作台 | 提供商编辑/新增及 OpenAI OAuth 导入默认值；账号配置和原保存按钮一同提交 | 逻辑未改 |
| 批量票据编辑 | 提供商多选 → 批量编辑 → 工作台；勾选才改，同值回显，不同值留空 | 逻辑未改 |
| 固定/轮换/动态采集代理、成功 IP 复用 | 网关默认代理策略及账号优先配置，支持 IP 管理选择和手填 | 逻辑未改 |
| 双链路验证、STATE 保存/注入、续采、守护 | 按当前账号/模型/凭据/工作区隔离；账号绑定业务代理参与复验 | 逻辑未改，不引入另一个上游票据实现 |
