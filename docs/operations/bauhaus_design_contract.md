# 包豪斯设计契约

本文定义 ByteSeek fork 现行的全站设计约束。适用于每次开发、修复、重构、上游同步及新功能，不授权额外重设计或业务改动；用户明确改变要求时，在新版本中说明原因并同步本契约。历史实现理由在[版本历史](versions/index.md)查询。

## 设计来源与适用范围

- 主题权威入口是 [Tailwind 配置](../../frontend/tailwind.config.js)和[全局样式](../../frontend/src/style.css)中的 `--bh-*` 变量，公共组件承担跨页的一致行为。优先复用，不在页面中另造一套颜色、圆角和阴影。
- 用户端、管理端、首页、登录、工作台、模型广场、API 密钥、排行榜、图表、空态、错误态、菜单、弹窗和引导均在范围内。新功能不可“先用上游原皮肤上线再补”。
- 纯后端开发仍应确认返回字段、状态与价格语义不会破坏前端呈现；没有 UI 改动时如实记为不涉及，不为遵循风格而强行修改页面。

## 视觉与语义

| 对象 | 固定约束 |
| --- | --- |
| 基础色 | 红 `#E1251B`、黄 `#FFCC00`、蓝 `#1450A3`；墨色 `#141414`、纸色 `#F4F0E6`。深色模式使用现有主题变量，不把黑字机械覆盖到深底。 |
| 结构与阴影 | 直角、清楚的 2–3px 实线边框、明确网格和字号层级；默认使用仪表盘同源的 `--bh-shadow` / `--bh-shadow-sm`（4px 无模糊硬阴影）。按压时位移并收短阴影，不混入柔光或模糊卡片阴影。 |
| 几何 | 三角形、正方形、圆形是背景和动态构图的基本元素；圆形装饰/头像不等于允许全站胶囊化。保留既有首页及全局三元素，不要求每个按钮塞满三种形状。 |
| 正常与异常 | 正常运行、LIVE ROUTE 状态、服务组在线和模型可用率使用绿色；失败使用红色，未知/无数据使用中性色，不能伪装成功。状态必须同时有文字/图标，不仅靠颜色。 |
| 价格 | 模型广场 Standard 全部价格项目以绿色强调，Fast 对应项目及选中按钮以黄色强调；输入、输出、缓存写入/读取、区间价和其它价格形态均不能漏掉。不改变数值、单位、舍入、阈值或计费逻辑。 |
| 用量与排行 | 热力图沿用随量变化的绿色；前三名大卡片保留红、黄、蓝填充，直接落在彩色底上的文案、请求/消耗等次级数值及右上编号和几何标记保持白色；大卡片内白底主指标框继续保留对应名次色。1/2/3 形状为三角形/正方形/圆形。下方榜单的小编号框保持统一白底，数值保留对应名次重点色；不得把“小框白底”误改为大卡片白底。 |
| 关键信息 | API 端点蓝色高亮，API 密钥相关卡片保留硬阴影；头像菜单内已配置的客服联系方式保留重点色。背景和品牌色不能降低文字、数值、焦点可读性。 |
| 表格与滚动条 | 固定表头沿用黄底墨字，固定数据列使用主题实体背景；全局与嵌套滚动容器沿用浅灰滚动条及深色模式适配。 |

具体布局和语义以 [HomeView](../../frontend/src/views/HomeView.vue)、[ModelPricingPanel](../../frontend/src/components/marketplace/ModelPricingPanel.vue)、[UsageRankingView](../../frontend/src/views/user/UsageRankingView.vue)和相关公共组件为当前实现证据；上游同步不能因为减少冲突而回退这些 fork 设计。

## 交互与动效

- 可点击控件应有统一 hover、active 按压、focus-visible 与 disabled 状态。复用 `Select.vue`、`Toggle.vue`、`DataTable.vue`、对话框及 `.bh-action-menu`；disabled 不应触发操作或误显按压反馈。
- 装饰不能挡住按钮和输入；手机端菜单/弹窗不可越界，长模型 ID/长英文文案有可访问的展示方式，不能产生页面级横向溢出。
- 保留首页动态几何、轨道和黑色走马灯。中文词组为“一站接入、统一管理、灵活切换、智能中枢、透明计费、智能分发、接口统一、全链加速、企业稳定”；切换英文才用相应英文。逻辑词表不重复，连续滚动所需的轨道副本不应形成逐词重复的呈现。
- LIVE ROUTE 整块保持可点击并进入模型广场。动效优先用 transform/opacity，避免高频重新布局；遵循 `prefers-reduced-motion`，无动画时内容和操作仍完整可用。
- 保留键盘、ARIA、校验、焦点和草稿状态契约。例如分组页签持续挂载，校验与引导能展开、切换到目标字段；不得为视觉简化改为条件卸载。

## 业务边界与同步

视觉适配默认只调整呈现和交互反馈，不擅自改 API 路径/字段、鉴权、计费、模型映射、配置含义、数据结构或后端策略。上游明确带来的业务变化独立审查和测试，并在版本记录中区分“上游功能变化”和“fork 视觉适配”。确需扩大业务范围时先获得用户授权。

同步先对照最近版本的“后续同步保留点”，检查上游新增组件及共享控件对所有使用页的影响。不可整文件选上游版本而丢弃本地风格，也不可为保留外观丢弃上游修复的功能和可访问性。

## 交付验收

- 逐项覆盖受影响页面及共享组件消费者，记录实际测试路线；至少检查桌面与手机、深浅主题、长文案、空/加载/错误状态和菜单/弹窗边缘布局。
- 核对三原色及状态例外、硬阴影、边框、按压、键盘焦点、禁用和减少动画；样式正确不能替代功能测试，单元测试通过不能替代浏览器视觉检查。
- 检查前端 lint、类型/构建、相关测试；范围较大时运行完整前端套件。API/迁移涉及的上游变化另跑相应后端验证。
- 在版本文档记明设备/视口、主题、mock 或真实环境、结果和未测范围。不得把有限页面抽查写成全站每条路径均已验证；有阻断问题不发布镜像。
