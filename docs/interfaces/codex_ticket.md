# Codex 可选票据

本文记录当前可选票据的采集、使用及管理员手动批次边界，不等于官方能力保证或满血判定。bh.035 沿用 sub2api 回退前快照策略，bh.036 按用户要求支持自定义接受长度、更多尝试次数及手动历史；不恢复 Metadata/AT 实验，发布状态见版本记录。

bh.039 补模型集合配置、长度信号提示及手机点击详情；信号只展示，不新增自动质量判定、废票或重采策略。

<a id="ticket_contract"></a>
## 开关与存储

后台“系统设置 → 网关服务 → OpenAI”提供独立保存的可选设置；管理员 GET/PUT `/api/v1/admin/settings/codex-ticket`，缺省关闭。bh.035 支持最多 20 条命名采集代理：地址加密，只返回 ID/名称/是否配置；已有项地址留空按 ID 保留，新项须提供地址，移除需确认后保存。`selection_mode=rotate` 仅在未获合格票后切换到下一条重试，`fixed` 一直使用 `fixed_proxy_id`。固定某条代理不保证该服务商的出口 IP 固定，轮换多条也不保证出口不同。

旧单代理 `harvest_proxy_url/clear_proxy` 兼容：原配置显示为 legacy 代理；只有不超过一条时允许旧字段修改，防止旧页面误删多代理。持久化仍镜像 `proxy_cipher` 为固定选项的密文，旧二进制回退只能用这一条。新 UI 带 `revision`，服务重读设置时发现版本已变化则拒绝覆盖；这不是跨实例数据库 CAS。配置存储不新增迁移，旧、新实例混跑时应关闭功能完成升级，再在新页面重新保存，不能让旧实例把整条 JSON 的新字段清掉。

实例每两秒重读设置，本实例保存即时更新；设置读取失联时停用功能，不无限沿用曾开启的快照。每次保存更换代次，旧代次票据和在途结果不可复用。探测间隔 6–3600 秒、重试间隔 1–30 秒；未配置间隔时沿快照使用六秒，显式值保留。bh.036 的 max_attempts 取消业务上限十次，接受正整数（不超过 JavaScript 可精确表示范围），未配置时为一次，新页面无代理时建议三次。手动逐账号模型最多执行填写次数，成功/不可重试错误/取消提前结束；自动仍受三十秒整轮预算限制，不保证用完所有次数。切到轮换且次数为一时 UI 草稿调整为三，保存后生效。

target_length 默认 292，可设 6–8192 字节（头大小边界），采集、缓存有效性、调度/注入和只读状态统一使用该值。仍须满足 HTTP 200、gAAAAA 前缀及无非法控制字符，不把指定长度解释为官方质量等级。修改长度也沿原保存换代规则使旧票退出使用，不自动转换已有票。

bh.039 设置新增 models（1–100 个精确上游模型 ID，默认 gpt-6-astra/gpt-5.6-sol），页面每行一个，trim/去重、单ID最多256字节、不含空白/控制字符；空列表拒绝，缺失字段沿用历史两模型。不支持通配匹配，列表不会改写用户请求或给账号增加模型权限。配置集合共用于自动循环、手动冻结任务、状态列表及原有最终出站模型缺票门控/注入；新增模型可能因无票暂不可接单，移除后不再由票据功能门控该模型，原模型路由与其它资格仍保留。多模型仍共用四worker与原预算，不能承诺每轮覆盖完整集合。

degraded_signal_length 默认为0（关闭），可设6–8192字节；采集响应的状态头长度精确命中时保存 diagnostic.degraded_signal=true。该布尔是管理员配置提示而不是官方事实，不参与 validCodexTicket、重试、账号schedulable或题目质量结果。同一长度同时配置为合格与信号时，两者独立：仍可获票并显示提示。未命中/关闭不显示，旧历史不追溯改写，配置保存仍换代取消旧任务。

票据 AES-GCM 加密后写入独立 Redis 前缀，最长一小时 TTL，不写账号 extra、updated_at、scheduler outbox、账号导出或普通 DTO。重启可在同一配置代次/凭据下读回 Redis；功能开启且缓存无法读取时，按缺票拦截对应模型。缓存网络故障后本实例只读查询退避一秒，避免号池逐号等待超时；不缓存有效票以绕过 Redis。代理密码在审计中整体脱敏。

## 探测和请求

自动采集只对独立、可调度 OpenAI OAuth 账号的已配置模型运行（缺省 Astra/Sol）；不含影子、Agent Identity、API Key、其他平台及已停调账号。bh.038 手动入口仅忽略账号 schedulable 开关，详见下方手动契约，不把手动例外扩散到自动采集或正常调度。最多四个 worker、自动整轮三十秒、单探测二十五秒，轮次结束等待所设间隔；全池大时游标滚动，每号不保证每轮都轮到。正常账号并发槽仍限制探测；每次重试前再校验账号/凭据/配置。集群轮次租约使用与旧版相同前缀并以 UUID owner 条件释放，单模型租约限制下轮重入。关闭取消在途轮次，已发请求可能仍消耗额度。

同账号模型只在未获有效票时重试并切代理；成功即停止，有效票剩余超过十分钟时跳过采集，临近过期从最近成功的代理开始。轮换失败的下一轮从最近失败代理的下一项继续；固定失败仍用指定代理。总预算可能使实际尝试数少于配置次数。401/403/429、明确认证/额度/限流/请求参数错误结束本轮，不为此换代理绕过限制。遵守 Retry-After（最多保存 24 小时），429 或明确限流即使无头也至少等一分钟；只退避合成采集，不修改账号调度状态。

探测发送快照同形 `input_text` 数组的固定 ping/pong 提示；HTTP 200、指定长度（默认 292）、约定前缀和有效时间只作为兼容筛选，不证明模型质量。合格头立即保存，不读取回答。未合格时最多读 8KiB/1.5 秒以识别 JSON/SSE 的固定错误分类或完成事件，超时取消该次 HTTP，原始正文不保存或回传。采集走单独代理和禁用重用的 H1 短连接，禁止重定向；不改变业务 TLS 指纹和账号代理。设置/凭据/工作区变动使缓存隔离键变化，不接收客户端写入的票据库。

bh.035 按用户选择沿用快照：有效票覆盖出站 HTTP 与 WS 握手的 x-codex-turn-state，包括已有客户端值；缺票、无效、过期或读取失败时，当前账号不进入对应模型候选，出站构建器还会复核并返回缺票错误。不现场采集、不重放业务请求，不修改 schedulable、质量检测标签或账号全局状态。基础/高级调度、粘性与 DB 复查、WS 后续模型检查使用同一门控；按最终模型匹配，旧版 compact 应用当前 fork 自己的 compact 映射/兜底次序，避免按原模型拦错。新票入库后下一次选择即可恢复，无需手动打开账号。WS 注入只对新握手生效，不主动断开或重新握手既有连接。API Key/其他平台、未命中模型、关闭时均原样。

没有移植文章的“业务收到 312 即废票重采”。合成采集拒绝不符合当前指定长度的状态；业务响应照原回合头中继处理。有效旧票在临期续采失败时继续使用至本地期限；长度不等于质量证明，一小时也是本地保存政策而非官方有效期保证。

## 账号级只读状态（bh.034）

管理员 GET `/api/v1/admin/settings/codex-ticket/status?account_ids=1,2` 按当前页批量读取已配置模型状态，最多 100 个正整数账号 ID 一次、去重处理、整体两秒预算。只访问当前配置代次/凭据对应的 Redis 与账号数据，不刷新令牌、不触发探测。返回 enabled/server_time/items，以及 bh.039 新增的当前 models 列表，逐号包含 eligible/collection_paused/models；模型状态包含固定状态、原因码及检查/过期时间，不返回票据、token、工作区或代理地址。bh.035 的可选 diagnostic 仅返回代理 ID/当前配置名称、尝试数、HTTP 状态、头是否存在/长度/前缀合格、响应类型、固定错误分类、是否见完成事件及重试退避时间。缓存诊断的任意错误字符串不会直接返回。

有效性和剩余时间以原加密票据本身为准；独立 `status:` 观测记录最多保留 24 小时，仅包含固定状态/原因码及时间，不改变账号配置与调度。采集前后仅增加有界缓存观测写入（单次 150ms），不增加上游请求或调度写入。新版本可读 bh.033 已缓存的有效票；没有历史观测时不伪造采集时间。有效旧票优先于最近刷新失败，已消失的票据不因历史成功记录被显示为可用。采集中超过一分钟仍无终态视为待采集，过期按真实时间判断；缓存读取失败显示不可用，不伪装为采集失败或“降智”。

bh.037 添加独立 `latest:` 展示缓存（同一配置代次/凭据/账号/模型键、24 小时 TTL），返回可选 latest 的来源 manual/auto、完成状态/时间、脱敏诊断和参考 IP。Redis Lua 按完成微秒时间原子比较，迟到旧写不覆盖新结果；多实例需保持时钟同步。自动记录最近结束的尝试，手动记录整个账号/模型结束结果（含跳过/取消）；不使用 latest 控制重试、缓存有效性、调度或质量标签。旧记录未回填，没有 latest 时保持原展示，缓存故障不伪造最新结果。手动每号模型完成和整批结束触发原状态 GET 刷新，在途轮询后合并补读，翻页/销毁仍取消旧请求。

账号管理“满血测试”列在原结果下方按配置模型分别显示。有效为绿字倒计时、未获合格票/过期为黄、采集失败红、采集中蓝、关闭/待采集/不支持/读取失败中性；原满血蓝/降智红/测试失败黄保持。诊断显示实际长度/target_length，不硬编码 292。独立 OAuth 才显示；API Key、影子和 Agent Identity 不显示票据块。当前页每十五秒只读轮询，原刷新按钮可主动读状态；每秒本地按服务端时间与单调时钟更新倒计时，不每秒请求。隐藏标签页不轮询，恢复时刷新；数据超过 45 秒不再信任其有效色。翻页取消旧请求、卸载清时钟；提示中的采集时间和原因只来自脱敏数据。

有 latest 时，同一列的模型主行展示“手动/自动 · 最新结果”，下一行显示当前票据倒计时或缺票状态；最新失败不会被旧有效票盖住，也不会把旧票判成失效。提示包含完成时间、最新原因和参考 IP 或固定查询失败原因。数据读取失败时隐藏 latest，不继续显示旧成功色；不增加表格列，不覆盖原满血题目测试结果。

bh.039 原列按服务端 models 顺序展示全部配置模型，Astra/Sol 保留简称，其它显示原 ID。实际/目标长度比值单独边框加粗：数值不等黄色、相等绿色（仅长度相等，不代表HTTP/前缀均合格），无头仍显示无头；信号命中红字显示“降智信号”。模型按钮支持点击/键盘打开 BaseDialog，手机也可看完整时间/代理/IP/原因，桌面 title 保留同源明细。移除用户指定 notQuality 长提示，不更改文档中的事实边界；账号切换、模型移除时关闭旧详情，读取失败不展示陈旧诊断。

模型状态增加 blocked 字段，开关开启且对应模型无有效票时为真；界面显示“该模型暂停”，不是账号总调度开关被修改。这里的“暂停采集”仍表示账号原本已不可调度；有效票也不代表账号可调度或模型满血。状态页面为只读快照，不是实时调度决策。发布与未测项见 [bh.035](../operations/versions/v0_1_278_bh_035.md)。

## 手动批量采集（bh.036）

管理员在账号列表勾选后确认发起 SSE 批次，使用网关服务当前配置及冻结模型列表，最多 500 个账号、去重冻结。POST `/api/v1/admin/accounts/codex-ticket-collect` 接受 account_ids、confirmed=true、revision；无配置/关闭/过时配置拒绝发起。每个账号×配置模型分别为一个进度任务；不符合类型/模型等资格的账号明确跳过。bh.038 在手动专用 context 下用账号副本忽略 schedulable 标志，入口/每次尝试前/保存票据前统一应用：关闭账号调度仍能手动采集，不临时打开真实开关、不写账号 updated_at/outbox。禁用/已过期自动暂停/限流过载或临时冷却、凭据/工作区变化、模型支持等检查保持；取得票不等于重新参与用户调度。自动仍检查真实 schedulable。

开启页/读历史不会执行采集。显式手动重新采集不先删除有效票，成功按原规则入库，失败保留旧票。手动跳过普通有效票/周期节流，但不绕过 Retry-After；按配置次数执行、不受自动三十秒预算限制，单次仍二十五秒、四 worker、原账号并发槽限制。

共用自动轮次 Redis 租约，最多等待三十五秒让在途自动轮次结束，失败返回忙碌；手动每十秒按 owner 续租四十五秒，并更新历史心跳。运行期间全局自动轮次被该锁阻挡，不另建无界并发。配置变动/关闭、失联设置、续租失败、停机或 SSE 断连均取消余下任务，不回滚已获票。不自动继续中断批次；SSE 的 start/attempt/result/heartbeat/complete 由单发送者输出，单次写入有界，缺少 complete 不显示完成。

迁移 275 的 codex_ticket_manual_runs/events 独立保存每次尝试与最终结果。每批保存脱敏配置（代理名称/ID，无地址），每次保存邮箱/账号、模型/目标长度、HTTP/头长度/前缀、错误枚举、代理名称、时间/耗时及参考 IP；不写票据、令牌、代理 URL/密码或原始错误正文。

bh.037 手动参考查询使用现有代理探测器的专用方法，不改变全站 ProbeProxy 默认端点：默认先 HTTPS ChatGPT `/cdn-cgi/trace`、再 HTTPS ipify，单端点五秒、总十一秒有界，不带 OAuth 认证/Cookie、不跟随重定向、不得无代理直连；管理员显式 security.proxy_probe.urls 继续优先覆盖。解析最多 8KiB，地址经 IP 解析后才能保存。先前 HTTP 默认端点受代理域名/协议限制、共享四秒耗尽是可能失败路径，未以生产实测确认唯一原因。

手动日志新增 ip_source 与 ip_http_status，ip_status 明确区分 reference/timeout/network/tls/http_error/invalid_response/proxy_config/cancelled/not_attempted/unavailable。无采集 HTTP 响应不会额外查询 IP；查询失败不改变获票结果，不记录错误原文。参考 IP 来自独立请求，动态出口可能不同；只显示参考值、来源和采样时间，不能称为采票连接的真实出口。旧历史没有具体失败类别不回填。该查询仅手动尝试执行，自动采集不增加 IP 请求。

GET `/api/v1/admin/accounts/codex-ticket-runs` 每页二十批；`/:id` 返回批次及 kind=result/attempt、status、account_id、model 过滤后的每页五十条记录。只对管理员开放。心跳超过六十秒的运行只读呈现 interrupted，不用 GET 修复/重跑；完成后拒绝追加。日志写入失败停止批次并显示执行失败，已取得的票不回滚。历史没有自动删除，次数没有业务上限时必须关注数据库容量；浏览器实时区仅保留最近五十次，完整日志持久化分页，结果按点击分类展示。关闭或换管理员取消请求并清展示，选中集合/确认不持久化。

bh.039 手动 total 为去重账号数×冻结模型数，列表变化取消旧代次任务，不混入正在执行的批次；历史config保存该批models和信号长度，diagnostic保存当时是否命中。查询任意合法模型ID，包括已从当前配置移除的模型，不把历史强制限制为Astra/Sol；旧历史缺新字段仍可读，不重算质量或信号。自定义模型通过原Responses合成采集，不代表支持模型专用其它协议。

bh.038 增加同一管理员路由族 DELETE：`/codex-ticket-runs` 清空全部已结束或六十秒失联批次（不是仅当前页），`/:id` 删除单批及级联明细，`/:id/events/:event_id` 仅删该批所属单条事件。按用户要求点击直接执行、不二次确认；页面说明不可撤销及范围。数据库先锁父批次并检查活动心跳，仍运行返回409；清空保留活动批次。删除失联批次后心跳影响行数为零会取消旧worker，后续日志无法追加，不重建已删历史。无新迁移，账号/有效票据/latest展示缓存/题目质量检测不在删除范围；只删单条结果时统计按剩余结果重算，不假装采集任务从未执行。清空/删除成功后刷新分页，失败保留展示，删除仅能从数据库备份恢复。

## 与上游的区别

与上游一致的是基于长度/前缀筛选、一小时缓存/提前十分钟续采、有效票覆盖回合头和缺票阻止对应模型候选。bh.036 允许管理员自定义长度，新增显式手动批次和历史，不引入文章额外判断。保留 fork 私有加密 Redis、凭据与配置代次隔离、有限并发、原账号资格约束、多代理失败切换和诊断。上游账号 extra 存储、无界全池并发不整段照搬；依赖固定加密密钥和共享 Redis。不会自动变更 schedulable、满血检测结果、计费或订阅规则。

票据仍按上游账号/模型复用，不是按平台用户签发的新凭据。本地 Key/session/response 归属隔离保持原样，但无法证明上游不透明 turn-state 在不同真实会话间的全部语义；不能据单元测试承诺“绝不影响质量或缓存命中”。单账号连接测试、手动/定时质量检测的独立测试请求不注入此票据，本功能不将合成 ping 当作质量检测结果。bh.035 仅在合成采集将 Astra 版本下限设为 0.153.4、Sol 设为快照默认 0.146.0，保留更高后台版本，不回写业务身份。采集的公共 ensureCodexIdentityHeaders 原本就带 experimental beta；之前“不恢复旧 beta”的文档表述已勘误，这次不是额外给正常业务加头。上游探测额度不记为某个用户的账单。
